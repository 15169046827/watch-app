# 手表应用审计补充规则（WATCH-APP-UPARS）

- Profile 编号：WATCH-APP-UPARS
- 版本：1.1.0
- 基准标准：全局技能 `$universal-project-audit` 中的 UPARS 1.0.0
- 适用范围：本仓库全部现有及新增手表应用，以及与其共同交付的桌面构建器

本文件只记录手表应用项目的附加要求，不复制或替代 UPARS。发生冲突时优先采用更严格的要求；任何降低全局要求的做法都必须按 UPARS 例外流程登记。

## 1. 项目范围

- `X3VoiceLedger`、`X3WolaiNotes`、`X3OfflineReader` 手表端及听读工坊：面向普通用户的 OPPO Watch X3 公共产品；
- `X3AccessibilityProbe`：内部诊断工具，不纳入公共产品发布定位；
- 共享基础设施；
- 后续加入本仓库的手表应用及配套工具。

## 2. 标准轨道与任务边界

- WACAS 1.1：代码审计与整改轨道；
- WARS 1.0：面向普通用户的公共安装版发布标准化轨道，规范文件为 `docs/release/WARS_1_0.md`；
- 两套标准并行但结论分离。不得把发布改造混入尚未完成的根仓库或 `X3AccessibilityProbe` 审计整改；
- 当前审计整改顺序保持为：根仓库/共享控制与 Probe、VoiceLedger、WolaiNotes、X3OfflineReader；
- WARS/WACAS 标准变更权属于协调任务。其他产品任务发现缺口时必须反馈，不得自行修改标准定义。

## 3. 手表端专项必审项

### 3.1 设备与交互

- 圆屏裁切、目标分辨率、字体缩放、旋转和主题；
- 表冠、触摸、返回、焦点、辅助功能语义和最小触摸目标；
- 前后台切换、息屏、进程回收、低电量和存储不足；
- 真实设备未验证的行为必须列为发布验收项，不能以模拟器或构建成功代替。

### 3.2 安全与隐私

- 网络能力默认关闭或由用户明确触发，不得静默修改设备全局网络状态；
- 麦克风、存储、通知和网络权限遵循最小权限，并覆盖拒绝、撤销和重试路径；
- token、Cookie、账号信息和语音/文本内容不得进入源码、普通日志或不受保护的导出文件；
- Android 组件导出、Intent 输入、文件 URI 和跨应用边界必须显式审计。

### 3.3 离线、数据与资源

- 核心使用路径应符合项目声明的离线能力；联网处理必须有明确提示和失败回退；
- 数据库迁移、导入、导出、断点、缓存和临时文件必须保证原子性与可恢复性；
- 音频、图片、压缩包和书籍输入必须检查路径、格式、容量与资源耗尽风险；
- 播放、录音、下载、同步等长任务必须正确处理生命周期、取消、并发、锁和资源释放；
- 审计电量、内存、存储和后台执行成本。

### 3.4 配套桌面构建器

- Windows/Vue/Tauri/Rust 组件分别执行适用的格式、Lint、类型、测试和生产构建门禁；
- 外部进程、临时目录、路径拼接、文件覆盖和打包操作必须验证目标边界；
- 桌面端生成的数据包必须与手表端解析、版本兼容和失败恢复逻辑联合验证。

## 4. 额度与可恢复性门禁

该门禁适用于所有 Watch App 开发、审计、整改、打包和发布任务：

- 进入工具调用、全量扫描、批量修改、构建或测试等密集阶段前，必须检查当前额度；
- 每个实质里程碑完成后再次检查额度；
- 剩余额度小于或等于 5% 时，不得开始新的修改；
- 触发阈值时必须保存完整、可恢复的检查点，至少包含当前基线、已完成事项、未完成事项、改动文件、验证结果和下一步；
- 未经用户明确授权，不得消耗任何额度重置权益；
- 向后续产品任务下发审计要求时，必须同时传达本门禁。

额度不足只限制开始新的修改，不得用来降低审计结论、跳过风险披露或把未完成事项标为完成。

## 5. 本仓库持续门禁

至少执行适用项目的规范、单元测试、Android Lint、Debug 构建及生产构建。发布前还必须执行：

- scripts/verify-network-safety.ps1 与 scripts/test-network-safety.ps1；
- scripts/verify-public-release-standard.ps1 与 scripts/test-public-release-standard.ps1；
- `scripts/verify-debug-signatures.ps1`（内部联调包）；
- 正式 Release 签名身份核验；
- Windows 听读工坊公开安装包的 Authenticode 状态与证书身份核验；
- 真实设备安装、升级、权限拒绝、离线主流程和恢复场景验收；
- X3OfflineReader 配套构建器的生产构建与端到端包兼容验证。

Java/Android 代码使用 `config/checkstyle/checkstyle.xml` 和 `gradle/android-java-quality.gradle` 作为仓库级最低规范实现。其他技术栈必须执行 UPARS 对应的最低门禁。

## 6. 报告与结论

- finding ID 推荐使用 `<项目>-<域>-NNN`；
- 报告必须明确区分手表端、桌面端、模拟验证和真实设备验证；
- “代码层审计通过”不代表“可正式发布”；真实设备、正式签名、安装包、升级和回滚验收必须单独判定；
- 新发现的通用风险按 UPARS 的标准补充流程处理，手表专属风险只更新本 profile。
- 报告应记录实质里程碑的额度检查及必要的可恢复检查点；不得披露账号或敏感额度标识。
