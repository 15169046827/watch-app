# Watch App 公共版发布标准（WARS）

- 标准编号：WARS
- 版本：1.1.0
- 状态：已批准，执行中
- 资产路径说明：文件名为兼容既有门禁与历史证据而保留；正文及机器规则的当前语义版本为 1.1.0
- 适用范围：`X3VoiceLedger`、`X3WolaiNotes`、`X3OfflineReader` 手表端及 Windows 听读工坊
- 不适用：`X3AccessibilityProbe`（内部诊断工具“能力测试”）
- 发布主体：个人；发布者名称 `Ym_Li`；当前渠道为 GitHub 直接下载 APK/便携 ZIP

WARS 管理面向普通用户的安装、升级、授权、隐私、数据和发布签名要求。代码审计仍由 UPARS 1.0.0 与 WATCH-APP-UPARS 1.1.0 管理；两条轨道分别给出结论。

## 1. 已批准的产品决策

1. 首次对外发布采用“个人 GitHub 预览版”；达到全部生产门禁后才能标记为正式公共生产版。
2. 所有 Android 公共产品共用同一把独立 Release Key；Debug Key 不得用于正式发布。
3. 笔记个人预览版允许用户自行填写个人 Token；默认未配置、明确提示其不是 OAuth、仅在本机加密保存且不进入 APK、日志或备份。正式公共生产版仍要求正式 OAuth。
4. 每个产品分别分析并实现适合自身数据模型的迁移、导出和清除能力。
5. 支付自动记账进入首个测试版，但默认关闭、单独授权，并在授权页和功能页明确当前识别限制。
6. Windows 听读工坊可发布明确标识的未签名便携预览 ZIP；未获 Authenticode 时禁止称为安装包或正式版。正式公共生产包仍必须通过 Authenticode 签名验证。

## 1.1 两条发布轨道

- 个人 GitHub 预览版：Android 仍须使用共享 Release Key；Wolai 个人 Token 由用户自行输入；Windows 只允许未签名便携 ZIP，并附未知发布者提示、源提交和 SHA-256。结论只能写 LIMITED PREVIEW。
- 正式公共生产版：Wolai 必须完成正式 OAuth，Windows 必须有可验证的 Authenticode，且所有设备、升级、迁移与回滚验收均通过。
- 预览轨道不得覆盖、绕过或降低正式轨道的失败关闭门禁。

## 2. 产品身份与兼容性

- 产品系列名为“日常工具”，启动器显示名保持简短：`记账`、`笔记`、`听读`、`听读工坊`；不强制添加系列前缀。
- 现有包名、应用数据目录和桌面应用标识原则上保持不变，避免破坏覆盖升级。
- 每次发布必须记录版本号、支持平台、数据迁移路径、回滚或恢复办法及已知限制。
- 已安装旧版必须优先使用覆盖升级验证；不得以卸载重装规避签名或迁移问题。

## 3. Android Release 签名

- Release Key 由维护者在仓库外生成、备份和保管；仓库及文档不得包含密钥、口令或证书私密内容。
- 四个 Android 应用产物（记账手表端、记账手机端、笔记、听读）必须使用同一 Release 证书。
- Release 证书必须与共享 Debug 证书不同。
- Release 构建从环境变量或受保护的 CI Secret 接收密钥位置、类型、别名、口令和预期 SHA-256；缺项、私钥不可解锁、证书摘要不符时必须失败。
- 对外 APK/AAB 必须再次独立核验签名身份，不能只依赖构建日志。
- 当前预登记 Release 证书 SHA-256 为 `3ef6162e5c749caf81d222642997ef306380fc96696c9661b77b72a829dc3f73`；四个 Android 公共产品必须全部匹配。

## 4. Windows 预览与 Authenticode

- 对外提供的听读工坊 EXE/MSI 必须有状态为 `Valid` 的 Authenticode 签名。
- 发布门禁必须核对签名证书 SHA-256，不能只检查“存在签名”。
- 未取得正式代码签名证书前，可以完成代码层和未签名构建验证，但正式发布判定必须保持“不通过”。
- 未签名预览只能是独立目录中的便携 ZIP，文件名和随包说明必须含 UNSIGNED-PREVIEW；不得生成 MSI/安装器，不得覆盖正式包目录。

## 5. 首次运行、授权与隐私

- 首次运行说明产品用途、核心离线/联网边界、数据保存位置、权限用途和清除入口。
- 权限按功能触发申请；拒绝或撤销后应保留可理解、可恢复的降级路径。
- 麦克风、网络、蓝牙、定位、通知和无障碍等敏感能力遵循最小权限。
- 凭据使用平台安全存储；日志、导出和故障报告不得包含令牌、原始支付页面、私密笔记或用户音频正文。
- 联网发送文本或音频前必须向用户说明接收方、用途和当前限制。

## 6. 数据迁移、导出与清除

每个产品必须形成自己的数据清单，并逐项标注：可迁移、需重新授权、可导出、可清除、仅缓存或不可恢复。最低要求如下：

- 升级迁移具有版本标识、失败回滚或安全重试，不得静默丢弃用户数据。
- 导出说明格式、范围和敏感性；导出过程使用安全目标选择并避免覆盖错误文件。
- 清除区分业务数据、缓存和凭据，展示影响并进行二次确认。
- 账号令牌、系统权限和设备配对凭据默认重新授权，不把秘密塞入通用迁移包。

## 7. 高风险功能隔离

支付自动记账必须同时满足：

- 首次安装默认关闭；升级不得擅自开启。
- 独立开关、独立说明、独立系统授权入口；关闭后停止采集并释放相关后台工作。
- 明确标注当前仅支持的应用、页面、字段和已知缺失；未确认结果不得自动写成确定账目。
- 只保留完成记账所需的最少字段，不保存原始无障碍节点树、截图或页面全文。
- 提供撤销授权、查看来源、纠错和清除相关数据的路径。

## 8. 发布门禁

每个公共产品进入对应发布轨道前必须通过：

1. UPARS/WATCH-APP-UPARS 代码层审计，无未关闭 P0/P1；P2 已关闭或按规则批准。
2. 规范、单元测试、Android Lint、Debug/Release 构建及适用的安全门禁。
3. Android Release 签名核验；Windows 正式版还需 Authenticode，未签名预览则核对预览标识、SHA-256、源提交及无安装器。
4. 干净用户首次运行、权限拒绝、离线主流程、升级、迁移、导出、清除和恢复验收。
5. 真实设备/目标 Windows 环境验收；模拟器或构建成功不能替代。
6. README、隐私说明、版本记录、已知限制和 Wolai 产品页同步。

代码层审计通过不等于可正式发布。缺少正式 OAuth 客户端或 Authenticode 证书时，可在满足预览轨道全部条件后发布 LIMITED PREVIEW，但正式公共生产结论必须保持不通过。
