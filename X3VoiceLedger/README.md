# X3VoiceLedger

OPPO Watch X3（OWW261）离线记账 App。项目与 `X3AccessibilityProbe` 完全分离；硬件和系统能力验证由探针项目承担。

两端启动器用户可见名称统一为“记账”。手表图标使用鼠尾草绿 `#8FAF7C` 的账单/条目/确认标记，手机图标使用桉叶青 `#4C9895` 的手机/同步循环；均按“日常工具”规范 v2.1 纯平面矢量重绘，不使用渐变、投影或母版裁切。底色完整覆盖正方形画布，API 26+ 使用纯色背景与透明前景组成的标准 Adaptive Icon，`icon`/`roundIcon` 同源；0.8.3 将两端自适应前景统一以画布中心缩放到 72%，在系统蒙版中保留均匀底色边框。

## 当前版本

- 手表端：`0.8.3`（versionCode 12），Android 11 / API 30。
- 手机伴侣：`0.8.4`（versionCode 15），compile/target API 35，已适配 Android 15/16 媒体权限。
- 无原生代码、收费云服务、Root、Hook 或 OPPO 私有逆向依赖。

## 手表端

1. 使用已安装的搜狗手表输入法语音输入，例如“午饭二十五元，在公司，用支付宝”。
2. 本地解析金额、说明、分类、账户、账本、标签、交易时间和地址。
3. 在圆屏安全区内逐项确认和人工修改后保存；记录以 UUID 存入 SQLite，离线可用。
4. 支持修改/删除已保存记录、从左向右滑动返回，以及在存在待同步账单时开启 BLE 同步窗口。
5. 可由用户在系统无障碍设置中开启“支付宝支付自动记账”：仅在已确认的支付宝 NFC 付款成功页生成本地草稿。

账单还保留原始语句、创建/更新时间、经纬度、定位精度和定位时间。定位不可用时，语音中的地址仍可写入地址栏。

## 蓝牙同步与一木导入

手机伴侣作为 BLE central，手表作为 peripheral/GATT Server。账单按 UUID 去重，手机持久化后发送 ACK，手表再标记为已同步。读取、ACK 和配置写入要求加密且具备 MITM 保护的 GATT 连接。

手机伴侣支持：

- 待导入、已归档、删除、批量导入、重新导入；
- 一木父/子分类候选确认；
- 查看本地已学习的分类匹配规则，并支持逐条删除或清空后重新学习；
- 编辑说明、账户、账本和标签；
- 通过一木公开 URL Scheme 写入 `asset`、`bookName`、`tags` 等字段；
- 手工维护与一木同名的账户、默认账户、账本和标签；
- 由用户主动选择一木导出的 `.xls`、`.xlsx`、`.zip`、CSV/TSV、文本或 JSON 文件，或在一木导出后的系统分享面板直接选择“X3 账单伴侣”；ZIP 会在本机受限解压后查找支持的导出文件。预览后从历史账单中去重提取账户、一级/二级分类、账本和标签，只合并配置，不导入历史账单；
- 把账户、动态分类目录、账本、标签库和默认项通过 BLE 同步到手表；
- 当手表账单未填写账户、账本或标签时，导入一木会使用伴侣中的默认项。
- 0.8.1 起首页采用低饱和灰青色、明亮留白和圆角卡片，突出待处理数量、金额、来源、状态和主要操作；所有内层弹窗同步使用圆角浅色背景、柔和按钮和分层字段标签。已验证的动态分类与导入流程保持不变。

一木没有公开的账户/分类读取或自动导出接口，因此 App 不读取一木私有数据库，也不会通过无障碍模拟点击导出或自动创建无法确认的分类。未来可在用户一次授权导出目录后自动发现新导出文件。

## 手表付款截图

手机伴侣可在用户授予完整照片访问权限后，仅监控 OPPO 健康传入的 `Pictures/com.heytap.health/screenshots/` 目录。它会离线识别已知支付宝“付款成功”版式的金额，按媒体 ID 去重，并生成待补充说明、分类和账户的草稿；普通表盘截图会被忽略，原图不会删除。

此路径只能在截图已经传到手机后工作。真机已确认：手机断连时手表直接提示截图失败，不在公共存储保留文件，重连也不会补传。因此截图导入不能作为离线自动记账路线。

独立能力探针已确认，支付宝 NFC 支付成功页可由第三方 AccessibilityService 读取“付款成功”和成交金额节点。手表端已实现产品服务：限定支付宝包与 NFC 成功页，必须同时命中 `nfc_pay_text` 的“付款成功”和精确 `tv_amount` 节点；不对其他金额字段回退，因此优惠/减免节点不会被记作成交金额。命中后离线保存金额、支付宝渠道和事件时间，以 30 秒短窗口防止页面重复事件生成重复草稿，并通过通知提示补充商户、分类和账户。当前页面未确认商户节点，因此不会猜测商户。

自动草稿保存后仍可在手表账单管理中修改；修改保留 UUID 并重新置为待同步，手机伴侣按 UUID upsert，不额外新建记录。首次安装后必须由用户在手表系统无障碍设置中手动开启该服务。

真实使用已确认，部分支付不会在前台展示包含成交金额的成功页，此时现有无障碍路线可能漏记；对应支付也未发现可用的系统通知记录，因此暂不引入通知监听作为兜底。自动记账当前属于尽力捕捉，语音或手工录入仍是可靠后备方案。

## 构建与签名

在项目目录执行：

```powershell
.\gradlew.bat :app:assembleDebug :phone:assembleDebug :app:lintDebug :phone:lintDebug
```

签名密钥不纳入版本控制。普通克隆使用 Android 标准 Debug 签名；内部维护环境若提供仓库根目录下被忽略的 `.signing/x3-debug.keystore`，则自动使用既有团队 Debug 签名。正式发布必须使用独立的 Release Key。

为保证无网络构建，BIFF8 `.xls` 读取库已固定为 `phone/libs/jxl-2.6.12.jar`；不要在构建时替换为不受控版本。
