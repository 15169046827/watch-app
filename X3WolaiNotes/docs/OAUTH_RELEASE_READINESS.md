# X3WolaiNotes 正式 OAuth 发布准备

- 核查日期：2026-09-12
- 当前状态：个人 GitHub 预览版允许用户自行配置个人 Token；正式公共生产 OAuth 外部能力仍未就绪
- 产品决策：个人 Token 只用于明确标识的 LIMITED PREVIEW；正式公共生产版必须使用可核实的用户授权流程；不得把 App Secret 或长期令牌放入 APK

## 官方能力核查结论

当前公开的 wolai Open API 文档目录只列出 Token、Block 和 Database 接口；Token 文档公开的是 `POST https://openapi.wolai.com/v1/token`，请求体需要 `appId` 与 `appSecret`。截至核查日期，没有找到可核实的用户授权端点、授权码交换、PKCE、作用域、回调注册、刷新或撤销接口。

参考：

- https://wolai.apifox.cn/
- https://s.apifox.cn/4ed28073-5c44-4c57-8e23-a29186d699ea/269227722e0

因此，现有 App Token 流程不能被当作移动端 OAuth。客户端不得猜测 OAuth 参数。个人预览版只接受用户在临时导入窗口输入的个人 Token；导入后只显示状态和时间，Token 不回显、不可直接修改，只能删除后重导。Debug 的 ADB 文件导入不得进入 Release。

## 放行所需官方信息

以下项目必须全部从 wolai 官方资料或正式支持答复中取得，并留存来源：

- 用户授权端点、令牌端点及 HTTPS 主机；
- 移动端公开客户端的注册方式与允许的回调 URI；
- 是否支持授权码模式与 PKCE S256；
- 可申请的最小读取、写入作用域及用户授权界面；
- access token、refresh token 的有效期与刷新规则；
- 用户撤销端点或明确的账户侧撤销步骤；
- 错误码、限流、授权失效和重新授权规则。

## 客户端安全基线

若官方支持移动端公开客户端，实施必须满足：

- 使用系统浏览器或受信任的系统授权界面，不在应用内收集 wolai 账号密码；
- 使用授权码模式、一次性 `state` 和 PKCE S256；校验回调 scheme、host、path 与 `state`；
- APK 中只允许公开的 client ID，不包含 App Secret；
- token 仅保存于 Android Keystore 保护的应用私有存储，日志、备份和导出均排除凭据；
- 权限最小化，授权失败、取消、过期或响应不完整时保持本地可用并禁止联网提交；
- 清除本机授权时删除密文、临时状态和 Keystore 密钥；若官方提供撤销能力，同时执行远端撤销并明确显示结果。

若官方只支持必须持有 App Secret 的机密客户端，则不得直接在手表 APK 中实现。需要另行批准、部署和审计可信中转服务，服务端保管密钥并限制用户、页面、作用域、速率、日志和数据保留。

## Release 放行测试

正式 OAuth 实现后，至少完成：

1. 干净安装授权、取消授权、拒绝授权和重新授权；
2. 回调 URI、`state`、PKCE、重复回调和过期授权码的正反测试；
3. token 刷新、撤销、远端失效、离线和限流恢复；
4. 最小权限下的速记写入、收藏与子页面读取；
5. 保数据覆盖升级后不泄露、不降级、不误用 Debug 凭据；
6. 导出、备份、日志和故障提示中无 token、App Secret 或私人正文；
7. 目标 OPPO Watch X3 上的圆屏授权交互与右滑返回验收。

任一官方参数、客户端注册、凭据安全或目标设备证据缺失时，正式生产发布结论保持 `FAIL / NOT READY`；这不阻止已通过预览门禁的 LIMITED PREVIEW。
