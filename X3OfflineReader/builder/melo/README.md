# Local MeloTTS runtime

Run `powershell -ExecutionPolicy Bypass -File .\builder\melo\setup-melo.ps1` once. It creates a self-contained Python 3.9 environment under ignored `.tools/melo`, installs the official open-source MeloTTS package and non-UI runtime dependencies, and prefetches the Chinese model. Gradio is intentionally omitted because the Builder uses its own local worker pool and does not expose Melo's web UI. No API key is used. Each worker stays alive for the conversion and loads its model only once.

The GUI offers accelerated (at most two workers) and low-memory (one worker) modes. Resource guards fall back to one worker when CPU or free physical memory is insufficient. Workers synthesize independent sentence WAV files concurrently, duplicate cache keys share one future, output order remains deterministic, and each concurrent process is limited to eight OMP/MKL threads on the current host. End-to-end uncached benchmarks were 78.78 s for one worker and 63.65 s for two; tested three-worker configurations took 68.16–71.32 s, so three workers are intentionally not exposed. The current CPU-only PyTorch runtime cannot use a GPU.

The model download needs network access only during setup/prefetch. Conversion is offline afterward: the Java provider forces Hugging Face, Transformers and Datasets offline mode for every worker. Hugging Face and NLTK caches are pinned inside `.tools/melo`, never a user-global cache, so the runtime can be moved or packaged. Setup also fetches the NLTK dictionaries that Melo imports at startup. The runtime retains `unidic_lite` and removes the empty `unidic` placeholder so MeCab can initialize on Windows without downloading the much larger full Japanese dictionary; Chinese synthesis is unaffected. Use `--melo-python <python.exe>` or `X3_MELO_PYTHON` to select an existing compatible environment.

The Java provider bounds each Melo request to 120 Unicode code points, splitting preferably at punctuation/whitespace and concatenating the resulting PCM WAV parts without a pause. A failed shorter request is subdivided further; a minimal request gets one clean worker restart/retry. The worker reports the Python exception class even when its message is empty, while Java retains only a bounded stderr tail for the on-screen failure diagnostic. No source sentence is written to that diagnostic.

For `ZH`, the worker applies NFKC to the spoken copy and converts characters outside Melo's actual Chinese-mixed frontend set (including `_`, emoji and CJK extensions) to pauses. If a basic CJK character still triggers Melo's pinyin assertion, only characters that fail Melo's own Chinese G2P check are replaced before one retry. Package building runs the sanitizer self-test. The authoritative content and Timeline text are never modified.
