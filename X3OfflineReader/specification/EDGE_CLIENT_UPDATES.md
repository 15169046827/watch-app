# Edge 在线连接组件独立更新

本机制更新客户端连接实现，不下载 Microsoft 语音模型，也不承诺自动推导未知协议。随包可复现基线为 edge-tts 7.3.1；Builder/Watch 版本及 OPBOOK v1 不变。

## 触发与用户控制

- 工坊启动后异步检查，默认开启；每天最多一次（失败也计入）。存储管理可关闭自动检查、查看实际版本/检查时间/结果，或强制手动检查。
- HTTP 401/403 暂停后，等待 Java 任务退出、释放运行状态，再额外检查一次。不开启自动检查时不触发；不自动续作，不重复上传私人正文。
- Tauri 的运行状态与原子更新标记互斥转换启动和检查；耗时工作在线程池执行，窗口仍可响应。检查不覆盖转换状态，失败不会使本地 Provider 不可用。

## 信任、下载与验证

1. 通过 TLS 验证访问官方 PyPI JSON API；wheel 只允许 HTTPS files.pythonhosted.org，拒绝重定向，元数据上限 1 MiB、wheel 上限 2 MiB。
2. 仅接受不低于 7.3.1 的 7.x 三段正式版本及未撤回的 py3-none-any wheel；拒绝预发行、降级和跨主版本。包内名称、版本、Requires-Python 和已安装 Requires-Dist 都必须匹配，不运行 pip、不安装/升级依赖。
3. 对比 PyPI 提供的 SHA-256。它提供下载完整性，不等于独立代码签名或对未来上游代码的人工审计；信任边界仍包括 PyPI 和 edge-tts 上游。组件更新不等于签名程序发布。
4. 压缩包最多 300 项、展开最多 8 MiB；拒绝越界、反斜线原始路径、符号链接、重复路径、.pth 和额外根目录。只提取 edge_tts 及其 dist-info（含许可），不安装播放辅助入口。
5. 使用候选组件向 Microsoft 发送固定公开中文短句，不读取任务或书籍；40 秒内获得非空 MP3，再由现有 FFmpeg 解码验证。网络或验证失败均不切换当前版本。

## 存储、一致性与失败保留

组件位于用户工作目录 components/edge；版本目录只创建一次，不覆盖。OS 文件锁防止多个更新进程并发；active.json 通过同目录临时文件与原子替换更新，并记录前一版本。下载临时文件在正常成功/失败后清理；原随包组件和已下载版本不自动删除。

Java Provider 在创建时固定组件目录与版本，每个句子进程均使用该快照，不跟随之后的指针变化。即使另一个独立工坊/CLI 进程完成更新，已经运行的任务仍使用原代码，旧版本文件不会被替换。指针缺失/无效时回到随包版本；已验证版本仍可能因后续服务变化失效，不保证永久可用。

新候选验证失败时旧指针保持原样，而不是先替换再尝试恢复。新任务使用原子启用后的版本；断点继续时重新创建 Provider，但缓存键、原音色、正文/时间轴语义和已有有效缓存不变。组件代码不纳入句子缓存键，与既有随包客户端升级一致。

若上游尚未修复协议、发布新主版本、需要新依赖/Python/证书，更新器会保留原组件并给出限制说明，仍可能需要更新工坊。它不绕过服务认证、限流或使用条款，不无限重试握手拒绝。

## 自动化验证

Python unittest 覆盖压缩包安全、哈希拒绝、Python/依赖兼容、版本边界、失败保留、成功启用/旧版本保留、每天节流与强制检查、并发锁和损坏指针回退。Java 测试覆盖指针与操作白名单；Vue 类型/规范/生产构建及 Rust fmt/test/clippy 验证桥接。实网验收只使用公开短句或自写公开样本，使用独立临时工作目录。

依据：[PyPI JSON API](https://docs.pypi.org/api/json/)、[Python Packaging Requirements](https://packaging.pypa.io/en/stable/requirements.html)、[edge-tts 官方项目](https://github.com/rany2/edge-tts)。
