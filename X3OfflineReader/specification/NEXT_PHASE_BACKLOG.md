# 下一阶段体验优化清单

状态：0.3.0 实现与 OPPO Watch X3 验收已完成。记录日期：2026-08-21，实施/验收日期：2026-08-24。以下项目保持小说/音乐数据与交互隔离，只复用底层播放器、MediaSession、Audio Focus 与蓝牙控制。

## P1：小说连续阅读体验

1. **上次播放章节定位**
   - 章节列表中为最近播放章节显示清晰的“上次播放”标记。
   - 进入章节列表后，默认滚动到该章节并保证条目处于圆屏安全区可见位置；没有历史记录时定位到第一章。
   - 使用现有持久化进度恢复，不以 Track ID 直接暴露给用户。

2. **统一听读同步文本区**
   - 合并当前“同步句子”与“可翻阅全文”两个窗口，只保留一个正文区域。
   - 正文区域以完整自然段为主要显示单元，当前朗读语句在段内高亮；不得因句子较长而截断同步文字。
   - 播放中锁定用户手动上下滑动，并自动保持当前高亮句可见；暂停后解除锁定，允许上下浏览正文。重新播放时回到当前朗读位置。
   - 切段、跨 Track、恢复进度、5× 倍速及圆屏裁切都需要自动化与真机回归。

3. **章节标题规则与列表排版**
   - 选取章节正文的第一段非空文本作为用户可见章节名称；需要定义去除多余空白、过长文本与无正文章节的回退规则。
   - 章节列表固定左边界、左对齐；单行显示不全时尾端截断，不启用横向滚动或跑马灯。

4. **隐藏 Track 分片**
   - 用户界面只展示逻辑章节，不展示 `1/2`、`2/2` 或 Track 名称。
   - 一个章节包含多个 Track 时，后台按 manifest 顺序组成同一 Media3 播放队列，自动跨 Track，并把进度、上一章/下一章、收藏与恢复统一映射到章节。无需在 Watch 上重新编码或物理拼接音频。
   - 尽量预备下一 Track，降低边界停顿；Timeline 仍按各 Track 独立保存，格式 v1 无需改变。

## P1：播放器与导入反馈

5. **上一项/下一项控制**
   - 小说播放器在圆屏左右安全区提供 `《 / 》`，语义固定为“上一章 / 下一章”；跨多 Track 章节时仍只按逻辑章节跳转。
   - 音乐播放器使用同样位置与样式，语义为“上一首 / 下一首”。
   - 与 MediaSession/蓝牙上一首、下一首动作保持一致，同时保留当前耳机固件可能不发送 AVRCP Previous 指令这一已知限制。

6. **小说与音乐播放模式分离**
   - 小说移除播放模式选择，固定按卷、章、Track 顺序连续播放。
   - 音乐保留“播完暂停 / 单曲循环 / 列表循环”，新增“列表随机”。随机模式需要定义不立即重复、队列耗尽后的重新洗牌、上一首历史栈和进程重启恢复行为。
   - 数据库设置迁移不得把旧小说模式污染到音乐设置。

7. **默认文件选择位置**
   - 小说导入优先把系统文件选择器定位到内部共享存储的 `Music` 目录，对应用户可访问路径 `OPPO Watch X3\内部共享存储空间\Music`。
   - API 30 优先通过 Storage Access Framework 的 `EXTRA_INITIAL_URI` 请求 `primary:Music`；OPPO 文件选择器不接受初始 URI 时安全回退到普通选择界面，不申请广泛存储权限。

8. **导入状态提示**
   - 小说显示“`文件名` 校验并建立索引（当前/总数）”，音乐显示当前文件名并同时显示“第 N/M 首”。
   - 0.5.0 不再复制或完整解压小说包；原地流式校验和索引期间避免重复提交，页面切换必须保留状态与按钮锁定，完成与失败必须给出明确结果，错误信息不得包含私人正文或敏感路径日志。

9. **章节内进度与一键续听入口（用户需求第 10 条）**
   - 分别保存每个逻辑章节的播放位置；再次进入该章节播放页时，自动从该章上次位置继续，而不是从章节开头开始。用户主动选择“从头播放”时允许清除或覆盖该章位置。
   - 同时保存整本书最近一次播放的逻辑章节及章内累计时间，在小说详情页提供醒目的 `上次听到：章节名  MM:SS　续听` 按钮；点击后直接建立该书队列、定位到对应章节与时间并开始播放。
   - `MM:SS` 使用逻辑章节累计位置。章节被拆为多个 Track 时，界面仍只显示章节时间，后台把累计位置映射到正确 Track 与 Track 内偏移，用户不得看到 `1/2` 等分片信息。
   - 进度至少在周期计时、暂停、Seek、Track 切换、页面退出、Audio Focus 中断和进程结束前的可用生命周期回调中持久化；异常、文件变更或位置越界时安全回退到最接近的有效位置。
   - 已完成章节需定义明确状态：从章节列表主动进入时可从头播放；书籍“续听”默认进入最近未完成位置，若全书已完成则显示“重新播放”而不是伪造续听时间。
   - 验收覆盖同一章重进、跨 Track 章节、切换其他章节后返回、进程重启、5× 倍速、暂停浏览正文后续播，以及详情页续听按钮的圆屏边界与文案截断。

## P2：电脑端音色选择与试听

10. **声音 ID 改为选择框**
   - 把可自由输入的“声音 ID”文本框改为由当前 `TtsProvider` 返回可用声音的选择框；切换 Melo/Windows/tone 时即时刷新选项，并分别记住上次选择。
   - 当前离线 MeloTTS 中文模型配置的 `spk2id` 只有 `ZH: 1`，所以 Melo 中文下拉框暂时只有 `ZH`；Windows SAPI 按本机实际安装声音列出，tone 只显示测试音色。没有可用声音时禁用转换并给出非技术化说明。
   - 显示名称可以友好化，但传给 Provider 和写入缓存键的稳定 Voice ID 必须保持明确，避免升级后错用音色。

11. **试听音色**
   - 在声音选择框旁提供“试听”按钮，用一段固定、无私人内容的中英混合短句，按当前 Provider、声音和语速生成并播放短 WAV。
   - 试听期间显示“正在准备/正在播放”，允许停止；重复点击不得并发加载多个 Melo 模型。切换 Provider/声音后应停止旧试听。
   - 试听临时音频在安全的应用工作目录生成并可复用短缓存，退出时清理；错误提示不得包含用户书籍正文，不改变正式转换表单、进度与输出。

12. **增加其他离线/在线中文 TTS Provider（0.4.0 已实现）**
   - 因当前 Melo 中文模型实际只有 `ZH` 一种音色，选择框与试听完成后仍需引入至少一个真正提供多音色的离线 Provider；继续复用统一 `TtsProvider`，让用户按 Provider 选择声音。
   - 第一优先技术验证 CosyVoice：官方项目支持中文、多语言、方言/口音、零样本音色和细粒度控制，代码为 Apache-2.0；必须先在当前无 NVIDIA GPU 的 Windows 主机上验证 CPU 速度、内存、模型体积、长文本稳定性、离线运行、模型权重许可及可分发性。
   - 轻量备选 Piper：新主线是 Open Home Foundation 的 `piper1-gpl`，本地 CPU 推理并支持中文管线，但主线代码为 GPL-3.0；旧 `rhasspy/piper` 已归档。需先评估许可证对便携包分发的影响、中文现有 voice 数量和自然度，不直接纳入产品包。
   - Fish Speech 能力强，但代码和模型权重采用专门的 Fish Audio Research License；完成许可审查前不作为默认产品依赖。
   - 新 Provider 必须输出句级 WAV/PCM，以真实时长生成 Timeline，保持 `.opbook` v1 的正文/同步/资源权威关系；不得打包或使用未经授权的真人克隆音色样本。

13. **转换计时可读性与静默心跳**
   - 用户复核后确认当前预计总用时基本准确；此前“33 小时被看成 33 分钟”属于单位误读，撤销 ETA 准确性缺陷及重新建模任务，不再把它列为待修复问题。
   - 长时长避免只显示容易混淆的数字格式：达到一小时时明确显示为 `33 小时 05 分`（可同时附 `33:05:00`），预计总用时、剩余时间、已执行时间和日志采用一致单位。
   - 进度区固定显示本次任务的“开始时间”和实时“已执行 HH:MM:SS”；同时显示当前里程碑/阶段名称及“本阶段已持续 HH:MM:SS”，让用户在进度不变化时可以判断模型加载、某句合成、编码或打包已经停留多久。
   - 已执行时间与阶段计时必须每秒独立刷新，不依赖进度百分比变化，也不能阻塞转换线程；切换阶段时重置阶段计时但保留任务总计时。成功、失败或用户取消后停止计时，并在日志中保留开始时间、结束时间、总耗时和最后阶段耗时。
   - 增加十分钟静默心跳：如果连续 10 分钟没有新的用户可见里程碑日志，但任务仍未结束，并且能确认 Melo/编码子进程存活且 CPU 时间、临时 WAV/M4A 或句级缓存至少有一项仍在推进，则追加 `转换器仍在正常工作，请不要担心（当前阶段：…，本阶段已持续 HH:MM:SS）`。
   - 心跳日志自身不算作真实进度，不重置“最后实际活动”时间；静默继续时最多每 10 分钟提示一次，新的真实里程碑出现后重新计时，避免刷屏。
   - 若 10 分钟内既没有新日志，也没有 CPU/文件/缓存活动证据，则不得误报“正常工作”；改为醒目的 `长时间未检测到进展，正在继续观察`，并提供当前阶段、持续时间及安全的取消/诊断入口。心跳检测不得记录正文、书名或私人路径。
   - 采用“自动一次、之后人工决定”的恢复策略：首次确认 10 分钟完全无活动后先警告并额外观察 2 分钟；仍无活动时只终止卡住的子进程，并自动重试当前最小可恢复步骤一次，不得从头重跑整本书。
   - Melo 卡住时重启对应 worker 并重试当前句；FFmpeg 卡住时只重试当前 Track 编码；最终打包卡住时只清理未完成的 staging/临时输出并重新打包。所有已验证完成的句级 WAV 缓存、章节产物和用户设置必须保留。
   - 同一步骤第二次无活动或失败后停止自动重试，界面提供 `重试当前步骤 / 继续等待 / 取消转换`。取消必须安全关闭子进程、保留可复用缓存并清楚说明下次重开能否续用。
   - 看门狗必须按 worker/FFmpeg/打包步骤分别跟踪，不能因为另一个 worker 仍活跃就掩盖单个任务永久阻塞；每次警告和重试在日志中记录阶段、无活动时长、重试次数及结果，但不记录正文或私人路径。
   - 自动恢复验收覆盖：worker 无响应、worker 异常退出、单个 worker 卡住而另一个仍工作、FFmpeg 无响应、损坏的临时 WAV/M4A、打包中断、自动重试成功、连续两次失败后的三个用户操作，以及重启程序后缓存继续复用。

## 计划顺序与完成证据

建议顺序：章节/Track 逻辑统一 → 章节内累计进度与详情页续听入口 → 统一听读正文区 → 上次播放定位与章节标题 → 上一章/下一章及音乐随机 → Music 初始目录与导入进度 → Builder 计时可读性与静默心跳 → 声音选择框与试听 → 新离线中文 TTS Provider 技术验证。

实现阶段需要补充：数据库迁移测试、章节内累计时间/跨 Track 映射/详情页续听与进程重启测试、章节多 Track Golden Sample、随机队列单元测试、圆屏布局/触摸锁定仪器测试、Music 初始目录回退测试、导入进度与失败测试，小时/分钟显示与静默心跳真假活动测试，Provider 声音枚举、选择持久化、试听停止/失败测试，以及新 TTS 的离线、速度、长文本、许可和包体评估；所有无需设备的开发完成后，再请求连接 OPPO Watch X3 做视觉、触摸、文件选择器与连续播放验收。

## 0.3.0 实施结果（2026-08-24）

- 已完成 1–11：逻辑章节聚合、多 Track 无感队列、章内累计进度、最近章节定位与续听按钮、第一段标题、统一正文高亮与播放时滚动锁定、小说上一/下一章、音乐上一/下一首及列表随机、Music 初始目录、多文件导入反馈、Provider 声音下拉框与固定短句试听。
- 小说固定顺序播放并移除模式按钮；音乐四种模式独立保存。数据库升级到 v3，并将旧 `book_progress` 安全迁移为章节进度。
- Builder 已增加下一章语音预取与当前章 M4A 编码重叠的流水线，保持输出顺序与缓存键不变；Melo 仍以本机实测最优的最多 2 worker 运行。
- Builder 已增加开始时间、总耗时、阶段耗时、明确小时单位、10 分钟无进展提示；Melo/FFmpeg 当前最小步骤 12 分钟无返回时自动终止并重试一次，打包失败也只重建 staging 并重试一次，句级缓存不清除。
- Builder 0.4.0 已用 Apache-2.0 sherpa-onnx 落地 Kokoro 中文 100 音色与 AISHELL-3 轻量 174 音色；新增当前动态枚举 14 个中文音色的 Microsoft Edge 在线 Provider。模型下拉框明确标注离线/在线，每个音色均可用固定公开短句试听。在线正式转换必须经 GUI 二次确认或 CLI `--allow-online-tts`，详情及未纳入候选的许可取舍见 `TTS_PROVIDERS.md`。
- 本地验证覆盖 Builder/Watch 单元测试、Builder 分发、AndroidTest 编译、Debug APK、Lint 和强制签名。OPPO Watch X3 上最终 15 项设备回归在 175.366 秒内全部通过，覆盖综合冒烟、两 Track 单逻辑章、跨 Track 连播/累计续听、统一文本高亮、5×、列表随机、Audio Focus、后台/右滑生命周期、熄屏、长播放、进程重启持久化与存储选择器。文件选择器探针确认系统 `com.android.documentsui` 工具栏标题为 `Music`，证明本机接受标准 `EXTRA_INITIAL_URI` 提示；其他固件忽略提示时仍安全回退普通选择器。

## 0.5.0 索引式书库（2026-08-27）

- 小说改为对任意 SAF 源文件持久授权并建立元数据索引；可寻址来源通过 ZIP 中央目录跳过音频全文扫描，不可寻址 Provider 回退顺序流，取消收件箱与整包复制/完整解压。
- 全局单任务协调器在页面切换后继续维持状态和按钮锁定；源 URI 与 `bookId` 去重。
- 播放缓存仅覆盖前一/当前/下一章节，优先随机读取可寻址 ZIP，回退顺序流；源文件缺失时不进入章节页。
- 小说和音乐列表支持长按管理。小说可仅移出书库或连同源 `.opbook` 删除；音乐可仅移出列表或连同音频删除。
- 2,742,410,282 字节 `.opbook` 已在 OPPO Watch X3 通过随机 ZIP 索引测试，总耗时 17.84 秒；源文件大小不变、临时目录清空、应用目录无超过 500MiB 的副本。该测试同时发现并修复旧 Builder 的句首 Unicode 空白范围偏差。文件授权和完整播放器回归已完成；缺失源、双模式删除与按需缓存仍保留非破坏性之外的专项人工验收。
