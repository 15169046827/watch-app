## 0.6.3 最佳并发与端到端实测

基准机为本开发机 12 核/16 线程、32 GiB 内存。测试使用 `builder/benchmark-tts.ps1` 内置的公开中文语料，每次注入唯一运行标识以绕过句子缓存；计时覆盖 Java 启动、解析、Provider/模型启动、语音生成、FFmpeg 编码和 `.opbook` 打包。下表采用最佳档的较长样本结果，代表长篇任务在本机的参考值，不是跨设备或在线服务 SLA。

| Provider | 最佳配置 | 本机长篇端到端实测 | 结论 |
|---|---:|---:|---|
| Windows 系统语音 | 2 个长驻进程 | 约 108.3 万字/小时 | 4/8/12 进程因争用反而下降，默认改为 2 |
| Microsoft Edge 中文 | 8 个并发请求 | 约 83.3 万字/小时 | 12 并发约 81.9 万且服务压力更高，默认保留 8 |
| AISHELL-3 | 4 个长驻模型进程 | 约 46.5 万字/小时 | 接近 50 万目标；受 CPU 推理上限约束 |
| Kokoro | 4 个长驻模型进程 | 约 8.3 万字/小时 | 音质/多音色优先，CPU 计算量最大 |
| MeloTTS | 2 个长驻模型进程 | 约 7.4 万字/小时 | 第 3 个进程在既有对照中更慢，继续限制为 2 |

以上效率随文本句长、音色、语速、缓存命中、网络和在线服务状态变化。GUI 模型选择处直接显示对应参考值；初始 ETA 使用同一组单路/最佳档实测曲线，运行中仍按实际进度校准。CLI 可用 `--melo-workers`、`--sherpa-workers`、`--windows-workers` 和 `--edge-workers` 复现实验或降低资源占用。

Melo、Kokoro、AISHELL-3 与 Edge 的试听资源在发布前生成并随包分发，统一为 16 kHz、单声道 PCM WAV；Windows 系统语音则使用固定公开短句在本机实时生成，不向网络发送内容。预生成器固定使用 1× 自然速率，不做 `atempo` 或其他后期变速；因不同模型/音色的自然时长差异很大，公开短句会按模型和音色缩短或延长，最终真实时长必须为 5–10 秒。Kokoro 19 个、AISHELL-3 44 个以及 Edge 3 个异常音色在调整文本后仍不合格，故不进入发布索引。

## 在线模型边界

Edge 下拉项始终标为 `[在线]`。枚举音色不包含书籍正文；在线试听只发送固定公开示例句。正式转换前 GUI 显示正文外发警告并要求确认，CLI 则拒绝静默使用，除非显式提供 `--allow-online-tts`。请求正文通过子进程标准输入传递，不放入命令行或日志；Builder 不保存 API Key（Edge 客户端不需要 Key）、账号或正文日志。

在线服务可能限流、变更或暂时不可用，因此离线 Provider 继续作为默认和可复现路径。edge-tts 7.2.8 的 `NoAudioReceived` 表示 WebSocket 到达 `turn.end` 前没有收到音频帧，但根因既可能是上游空响应，也可能是本地提交了不可发音文本。本次真实任务的首个未缓存片段经隐私保护分类后只有一个 `FINAL_QUOTE_PUNCTUATION`：旧切句器在句号处立即截断，把右引号拆成独立句，故 25 次相同请求必然全部失败。新切句器把右引号、右括号等闭合标点归入前一句并过滤纯标点片段；Provider 在联网前再次要求至少包含文字或数字，且会越过闭合标点判断真正句末。只有通过该预检仍收到空音频的请求才按 2/5/10/20/40 秒、随后 60 秒的上游恢复窗口重试；保存或暂停可中断等待，缓存与音色不被替换。

Edge 的句级任务可设置 1–12 个并发请求，新任务默认 8，旧断点按 1 兼容。Builder 会先建立全书 Future 队列，再按原章节与句子顺序等待结果和写入 Timeline，因此并发完成顺序不会改变书籍顺序；成功句仍原子写入同一缓存，章节 M4A 编码与后续语音生成重叠执行。并发重试带 250–1500 ms 错峰，降低瞬时故障后的同步重连。并发上限不是服务承诺：网络质量、服务限流和音频时长都会影响扩展效率。

旧单并发真实长书任务的 30 分钟窗口约为 847 句；按该任务平均句长折算约 5.3 万字/小时。0.6.3 公开长样本端到端复测已确认 8 并发约 83.3 万字/小时，12 并发不再提速，因此不继续无限增加线程。在线实效仍受网络、Microsoft 服务限流和音频时长影响；失败会继续按可中断恢复窗口处理，不以丢句换取吞吐。

## 许可与候选取舍

- [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) Runtime：Apache-2.0。
- [Kokoro-82M v1.1 zh](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)：官方模型卡标记 Apache-2.0；sherpa 导出保留 100 个中文 sid。
- [AISHELL-3](https://www.openslr.org/93/)：语料公开页/论文采用 Apache-2.0；使用 sherpa 官方 VITS 导出。
- [edge-tts](https://github.com/rany2/edge-tts)：客户端为 LGPL-3.0（上游注明的单文件例外除外），但 Microsoft 服务和音色模型本身不是开源模型。
- Piper `zh_CN-huayan-medium` 未纳入：上游模型卡把底层 HuaYan 数据集许可标为 `Unknown`，不能因为运行时代码许可开放就推断音色权重可安全分发。
- CosyVoice、Fish Speech、GPT-SoVITS、零样本克隆类模型本轮不随包分发：模型更大、Windows CPU 长书吞吐或权重/训练数据许可尚未达到可复现的便携发行门槛。不得随包加入未经授权的真人参考音频。

第三方随包清单见 `builder/THIRD_PARTY_TTS.md`，安装脚本固定 Runtime/客户端版本，不写入凭据。

## 验收门槛

每个新增离线模型必须完成：固定短句、Unicode 标点、至少一段长文本、完全断网、WAV 时长、整包 v1 Schema/跨文件/压缩包攻击校验；记录冷启动、实时率、峰值内存和包体。在线 Provider 另测无授权 CLI 拒绝、GUI 警告、正文不进入命令行/日志、网络失败可读错误。
