# Watch 索引式书库与按需播放缓存

## 用户语义

- “添加书籍”表示选择源 `.opbook`、保留 SAF 访问授权、安全校验并建立书库索引，不表示复制文件。
- 源 `.opbook` 是书库唯一权威副本，添加完成后仍需保留在原位置；移动、删除或撤销授权后，App 必须提示源文件不存在。
- 长按书籍提供“仅从书库移除”和“连同源文件删除”。仅移除会删除索引、缓存、进度和收藏但保留源文件；连同删除必须先成功删除源文件，再清理书库，失败时书库保持不变。

## 索引流程

1. 系统 `ACTION_OPEN_DOCUMENT` 支持一本或多本选择，App 请求并持久保存读权限；Provider 授予写权限时同时保留，以支持用户主动删除源文件。
2. 全局单线程任务处理每个 ZIP，限制 4096 条普通文件、512MiB 单项、4GiB 总展开量、256MiB 元数据、16MiB JSON、8MiB 封面和 500 倍压缩比。
3. 本地 DocumentsProvider 等可寻址来源直接从 SAF 文件描述符解析 ZIP/ZIP64 中央目录并按位置读取条目，不依赖 `/proc/self/fd` 路径。添加阶段只完整读取元数据与封面，不再逐条打开数 GiB 音频；不可寻址 Provider 才使用固定 64KiB 缓冲顺序流验证，并每处理约 4MiB 主动短暂让出 CPU。
4. `manifest.json`、`checksums.json`、正文、Timeline 和封面写到临时元数据目录。添加时验证格式、关系、文本范围、校验清单完整性和全部非音频文件 SHA-256；音频媒体头与内容 SHA-256 延迟到首次播放提取时核对，验证通过前不得交给解码器。
5. SQLite v4 保存源 URI 和索引根路径。相同源 URI 直接跳过；相同 `bookId` 拒绝重复登记。失败或重复选择释放无用的持久授权。

## 页面与生命周期

- 索引任务不属于某个 Activity。离开书库再返回时，状态文字和“添加书籍”按钮锁定由同一个协调器恢复；同一进程内不能并发启动第二个索引任务。
- App 异常退出留下的临时元数据会在下次索引开始前清理。源文件从未复制到临时目录。
- 点击索引书籍前检查源 URI；缺失时不打开章节页，提示用户恢复文件或长按移出书库。旧版完整导入且没有源 URI 的书籍继续按原目录播放。

## 播放缓存

- 正文和 Timeline 来自已验证的元数据索引。音频不直接从 ZIP 交给 Media3。
- 进入播放器前准备前一、当前和下一逻辑章节的 Track；每个缓存文件写入同目录 `.part`，完成 M4A 头和包内 SHA-256 校验后再替换正式文件。
- 本地 DocumentsProvider 通常提供可寻址文件描述符，读取器通过自有 ZIP/ZIP64 中央目录索引随机提取目标 Track；不可寻址 Provider 回退为顺序流。
- 章节切换后更新三章窗口并清理窗口外缓存。写入期间至少保留 64MiB 可用空间；单 Track 仍受 512MiB 上限约束。

## 删除与兼容

- 删除书籍时先停止共享播放服务并清除系统媒体返回目标，再处理数据库、元数据索引和音频缓存。
- “连同源文件删除”依赖 Provider 写授权。Provider 拒绝删除时向用户报告失败，不移除书库记录。
- 音乐库保持独立数据库。仅移除音乐会把其路径记入隐藏表，避免下次扫描自动加回；连同删除会删除音频及已关联的 LRC。
- `.opbook` 文件结构和 `formatVersion: 1.0` 不变；0.5.0 改变的是 Watch 的存储与读取策略，不改变 Builder 输出契约。
- 新 Builder 会用同一空白规则同时裁剪 Timeline `text` 与 `startChar`/`endChar`。Watch 仅兼容旧 Builder 已知的句首 Unicode 空白偏差，并要求扩大后的原文切片与 Timeline 文本完全一致；其他文本不一致仍拒绝导入。
