# 日程用途与兼容

0.2.0 新建日程时选择 EXECUTION（执行型）、REMINDER（仅提醒型）或 TODO（待办型），用途独立于内容大类。旧计划/实例/事件快照缺失 kind 时默认执行型，原语义不变。

- 执行型：原有周期、开始/完成/继续/请假流程；参与执行报告和优化。
- 仅提醒型：单次或周期，仅一次开始/提前提醒，不打卡、不催促、不进入待确认或执行统计。
- 待办型：单项，可无时间或设置截止时间，支持完成和重新打开；仅有截止时发送一次截止/提前提醒，不参与执行完成率、请假额度或优化。重新打开不重复已发送的同一截止提醒。

## 身份与历史

时间日程可通过未来分段切换执行/提醒；已开始或有记录的实例保留原类型，离线执行快照不会因后续编辑被抹去。

待办 todoDue 为空表示无截止；有值为计划时区的本地日期时间，精确到分钟。timed=false 的实例 start/end 为零，不虚构执行时间。实例 ID/date 使用不可变创建锚点，改截止不改身份。待办总会生成，不随滚动历史/未来窗口消失。

待办编辑使用最新手机定义，完成/重开按事件顺序保留；移除保存取消标记，旧完成快照不使其复活。旧页面不能给本机已移除待办打卡。待办不使用人工修正优先级，避免压过后续重开。事件不能改变待办与时间日程之间的身份。

本版待办不使用周期或分段，不直接与时间日程互转；可分别新建并保留原历史。超截止待办继续留在清单，标记“已到截止时间”，不当作执行失败。截止变化产生新提醒键，历史提醒不会反复补发。

## 升级与备份

三类型初次引入于 versionCode 2 / versionName 0.2.0；Snapshot/ACK protocol 2；wire schema 3；数据库 user_version 3。两端都须升级。旧客户端不能打开新版数据库或把新类型按旧语义处理。

v1 → v2 维持原迁移；v2 → v3 将旧 outbox 原样改名为 legacy_outbox_v1，保留全部消息 ID、正文和 revision，不删除行；新建独立 outbox。新 revision 为原 revision、旧队列最大 revision、acked_revision 中最大值加一，acked_revision 不变。新版从完整本地权威数据重新生成快照，仅匹配 ACK 后确认。旧队列保留追溯、不自动清理、不向新协议发送。

plans、instances、events、inbox、settings、suggestions 保留，不清库。旧 JSON 读取时补充执行型默认字段，拒绝数据库降级。手机备份恢复入口允许 protocol 1/schema 2，并验证只有旧执行语义，再提升为新版；实时同步不接受旧格式。伪装旧协议却含新类型的文件拒绝。

备份保存三种定义、实例、完成/重开记录。0.2.1 默认采用独立 32 MiB 上限的分块文件，旧 JSON 导入仍为 2 MiB；均未加密，详见 BACKUP.md。

## ICS

仅交换带时间的 EXECUTION/REMINDER 单次 VEVENT。导出 X-X3SCHEDULE-KIND 保留用途；无此字段的外部事件默认 REMINDER。不支持 TODO/VTODO 或完成记录，导出按钮明确“不含待办”，完整数据用分块备份。

校验一个完整 VCALENDAR、VERSION:2.0 和正确 VEVENT 嵌套；拒绝截断/拼接、容器外内容、嵌套组件、邀请/取消消息。原有严格日期、秒级时间、重复 UID 校验保留；文本导入拒绝非法 UTF-8。系统日历双向同步仍后置。

## 验证边界

领域测试覆盖类型隔离、旧数据/备份、待办时间窗口与操作顺序、改期/取消、统计/提醒、快照身份、ICS 容器。主机 SQLite 测试验证旧队列字节和未确认 revision 保留。Android 合成双端待办生命周期及事务测试仅构建，尚未真机运行；BLE、提醒、圆屏和覆盖升级保数据仍待设备验收。


0.3.0 后续升级：BLE 批次协议为 3、数据库为 4，内部 Snapshot 仍为 protocol 2/schema 3；三用途语义不变。两端须同时支持新分批协议。v4 保留 v2 outbox 并新增分批暂存/收据表，详见 PROTOCOL.md。

## 0.5.0 日历精度

三种用途不变。仅提醒型可设全天及含首尾的多天范围；执行型使用具体时间、可不设结束或明确跨日结束；待办可无截止、按某天截止或精确到分钟。dateOnly 与 daySpan 保存上述区别。默认按天提醒时刻可在设置修改，未设为09:00；按天待办保留至当天结束。月日重复跳过没有该日期的月份，按年重复跳过不存在的闰日。

内部 Snapshot schema4、SQLite5，外层BLE批次协议3。旧schema2/3备份验证后迁移，实时同步只接收schema4。实例ID继续绑定原发生日，单次改期另存实际日期，不改历史身份。详细编辑范围及投影见 CALENDAR_UI.md。
