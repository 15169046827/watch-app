# 等级事件模型（0.7.x）

## 数据版本与旧数据

- SQLite 6，Snapshot schema 5，BLE 批次 4；两端须同时更新。备份容器仍为 v1。
- 旧计划和实例的 `progress` 为 null，继续旧规则；普通 TODO 不自动计分。
- 新执行任务保存 `Progress.Options`；实例冻结标准、权重版本、任务日边界、任务时区及请假配额作用域。
- 旧 schema 4 只在备份迁移入口升级，不能作为实时同步；不能夹带新等级字段。迁移保留业务、设置、设备选择、已提交收据，清理未完成的旧协议暂存。
- `Action.PROGRESS` 与 `Progress.Entry` 一一对应，旧动作不能伪装新反馈。手表只能反馈、启用无冲突补救和请假，不能发送时间表编辑或让位操作。

## 不可变事实与结算

- Session 分为 ORIGINAL、SCHEDULED、MANUAL；Op 单独表达成果、启用、取消、重排、请假、让位/撤销让位、单日备用调整、冲突确认与停用备用。
- 选择正式补救后的累计等级表示有行动，即使没有升档；明确没有补救则保留原成果并锁存该承诺的失约。
- 实际成果与统计权重分离。Perfect 为100/80/60，Basic 为60/45/30，Minimum 为30/15/5，None 为0，依次对应零/一/二次失约。
- 未反馈为独立状态，不产生 None。None 不可通过更正抹去；后续补做保留前面的失约。
- 三档标准全部空白时只允许 Perfect/None；部分填写拒绝保存。
- 二分模式的0分表示“未完成”，不自动等于完全没做：选择0分时进一步确认有行动或完全没做，仅后者形成失约；有行动但未完成仍然只有0分，不新增中间等级。之后自行补做可提高至100分，已确认完全没做的失约保持不可撤销。
- 同一事件ID重复传输不重复结算；配额竞争按不可变确认时间、设备和ID决定，超额的原始事实保留。
- 成果更正使用 CORRECT 引用原始 RESULT，保留两条原始事实。仅允许更正仍表示有行动的记录；将其更正为未进行需要二次确认，此后不能再撤销该失约。

## 时间与冲突

- 普通日历使用自然日期；任务日默认当地04:00，实例保存当时边界。按当地日历计算边界，不能用减四个实际小时替代夏令时规则。
- 任务日D的补录到D+4任务日边界之前有效，即可补录过去三个任务日；界面展示具体截止时间。
- 不定时执行任务使用独立的任务日范围，不占时间轴固定时段、不产生定时失约。
- 不定时任务可以单独选择提醒和反馈时刻；默认采用全局提醒时间及任务日结束。边界时刻作为提醒指当天开始，作为反馈指次日结束；静音时段仍统一生效。
- 正式补救只能在未来、原时段结束后且不晚于原任务日结束，每实例最多一个；开始前允许取消/重排。
- 启用预览保存冲突指纹，提交事务内重新计算。未预览的新影响不能被默许；已承诺补救不能被新安排静默覆盖。
- 剩余比例按最长连续空档计算。60%和30%阈值决定提示或必须让位/调整；不自动顺延其他任务，不级联创建补救。
- 冲突滚动检查未来七天，确认静音只对应当前实例与相同指纹，变更时间/影响会重新提示。每日冲突摘要使用非精确提醒路径。
- 冲突指纹记录实际占用时段和规则，不因单纯经过另一任务的开始时刻而变化。已有明确同意的相同影响不重复提示。
- 离线补救编辑引用已观察到的上一条补救安排事实；并行分支保留全部事实，暂缓评分并提示手机核对。开始前可取消/重排；开始后不编辑历史安排，结束后在手机明确核对当前显示的时段再反馈。归并顺序使用逻辑时钟、设备和事件ID，正式补救只计一次。

## 展示与待验证边界

等级卡片按实际成果着色，月及以上按有效任务的等权平均权重着色；未反馈、未来、不计分和有效豁免不作为零分。显示向下取整以避免显示值跨入不同色档，无分母显示“暂无评分”。沿用现有浅色手机/深色手表体系和已验收启动器资源，新增单色通知图标。
