# 本地蓝牙分批同步协议 4

0.7.0 / versionCode 17开发候选，两端均须升级。BLE 批次协议为4，内部 Snapshot JSON 为 protocol 2/schema5，SQLite为schema6；三者不可混淆。旧手机 JSON 与 .x3backup 文件只通过备份迁移恢复，旧实时协议不再作为业务消息接入。新等级与补救事实见 PROGRESS.md；本版本尚未完成设备验收。

## 绑定与传输

GATT service 为 bcb71eb0-7600-46ea-8cf0-4838947ab001，Data characteristic 为 bcb71eb0-7600-46ea-8cf0-4838947ab002。使用 write-with-response / read 与加密 ATT；两端仅操作用户明确选择、已经系统绑定的对端地址，不扫描、不用设备名称认证。设备 ID 是数据来源标识，链路身份来自蓝牙绑定和所选对端。

外层帧：1 字节 kind + 4 字节大端正文长度 + 正文。kind 3 为分批数据（正文不超过 131584 字节），kind 4 为回执（最多 256 字节），kind 5 为拉取下一份手表分批（正文必须为空）。解析器保留旧 kind 1/2 供既有离线兼容测试，实际 BLE 业务分支拒绝旧协议。每次 ATT 传输初始 20 字节，MTU 成功协商后不超过 min(180, MTU−3)。帧内断连从该帧开头重发，已确认的完整批次页无需重发。

读取使用应用游标，offset 只能为 0；不是 ATT read-blob。一个进程共用串行蓝牙后台线程，旧连接清理在新连接启动之前执行；数据库与归档重组不在界面线程运行，状态通知回到界面线程。

## 归档与分批数据正文

数据使用 BACKUP.md 中的有界归档作为内部载荷：整体最大 32 MiB，最多 1000 计划、各 50000 实例/事件；内部 JSON 块仍有 2 MiB 及严格输入限制。手机归档含完整定义、实例与事件；手表归档不含定义/实例，只含本机事件，禁止人工修正。SnapshotArchive 共享编解码；用户备份入口仍只允许手机来源。

将归档连续字节分成 128 KiB 页，最后一页可短，最多 256 页。分批正文按以下次序编码（整数大端，字符串为 Java DataOutput.writeUTF；协议标识字段只允许 ASCII，因此是两字节无符号长度+ASCII）：

- int32：协议 4。
- UTF：批次 id、source（phone/watch）、deviceId。
- int64：冻结的 revision。
- int32：count、bytes（整份归档字节数）。
- UTF：整份归档 SHA-256 的 64 位小写十六进制字符串。
- int32：从零开始的页 index。
- 剩余正文：该页原始归档字节，无其他尾随字段。

id/deviceId 为 1–80 位字母数字、下划线或连字符。revision 非负，count 必须等于 ceil(bytes/131072)，bytes 在 1..33554432 内。页长必须与 index/count/bytes 精确一致。每页的元数据完全相同，并须与最终解码出的 Snapshot id/source/deviceId/revision 相同。整份归档还有自身结束标记和摘要。摘要检测混块与损坏，不提供身份认证或加密。

## 两级回执与发送持久化

回执正文：int32=4、UTF 批次 id、int32 index、UTF 原始分批正文 SHA-256、单字节 committed（只能 0 或 1），立即 EOF。

committed=0 只表示这一页已持久暂存；发送端前进游标，不推进 acked_revision，不释放整份发送副本。最后一页若仍收到 committed=0，说明接收端尚未收齐，发送端将游标回到 0；接收端对已有同内容页去重，最终可补齐丢失暂存。committed=1 只允许在最后一页返回，且只在完整校验与应用数据库事务提交后返回。

batch_out 保存不可变 manifest 与 next 游标，batch_out_parts 分行保存最多 128 KiB 的原始页，避免用超过 Android CursorWindow 的单个 BLOB。生成所有页和 manifest 同事务。发送端只接受当前批次/当前页/精确正文摘要匹配的回执；收到整份确认后，在单事务中推进 acked_revision、更新 last_sync、释放已确认的传输副本。生成快照之后的本地改动仍待同步。v4 迁移曾保留旧 protocol-2 outbox 与更旧 legacy_outbox_v1；v5 清除 outbox 及未完成 batch_out/batch_in 和分页，保留 legacy_outbox_v1、已提交收据及 acked_revision，递增本地 revision 重发新语义快照；业务数据始终以 plans/instances/events 为准。

## 接收暂存与原子提交

batch_in/batch_in_parts 保留一个尚未提交批次；每页暂存事务提交后才返回页回执。相同批次/页的内容不同立即拒绝。不同批次只有第零页可替换旧暂存；同一 deviceId 的 revision 不得比暂存批次旧。仅清理未应用的暂存，不删除计划、事件或发送端副本。新来源仍须通过所选蓝牙对端及角色方向检查。

收到最后一页且数量完整时，在同一 SQLite 事务内流式重组归档、验证摘要/结构/版本/数量/跨块唯一性/角色、合并计划和事件、保存 batch_receipts 中的 manifest 与全部页摘要，再释放已提交暂存。相同版本计划正文冲突或相同事件 ID 内容冲突使整个事务回滚：原应用数据、待同步修订及之前暂存页保留，最后一页未确认。冲突不会通过删历史自动解决，当前没有冲突批次的人工重建入口。

完整合并延续原规则：只有手机编辑定义；新版本替换、旧版本不回退；已有执行历史冻结；不可变事件按 ID union。手表按来源保存已接收 revision，旧归档不回退定义/实例；历史事件仍按不可变约束合并。完成后的重传逐页对照持久收据，最后回执丢失不会重复应用，改内容重传会拒绝。收据暂不自动淘汰，长期磁盘增长需后续归档策略。

## 双向交换

手机写一页 → 手表依次提供该页回执和自己的一页 → 手机确认该回执、接收手表页并写回执。手机批次未整份确认则立即继续写下一页；手机已完成、手表未完成时，手机只发空 kind 5 拉取，避免反复新建手机批次造成无法结束。双方均整份完成后休息约一分钟再检查本地变化。仍为完整快照同步，不是按变更增量同步。

提醒安排在数据提交后独立执行，提醒权限或调度失败不会阻断已经提交数据的回执。应用租约、伴随设备观察和手表前台服务沿用既有机制；强行停止、Doze、权限撤销及厂商省电的真实可靠性待实机确认。

## 验证边界

电脑端覆盖大于 2 MiB 的归档与 180 字节物理分片往返、整份组装、回执丢失/错误/过早确认、接收进度丢失后的回卷、元数据复原、混页/截断/摘要错误、不同大小双向交换、角色约束、帧限额。SQLite 主机测试覆盖 v4 无损迁移、页/活动批次约束、合并与收据/暂存清理回滚。Android 合成数据库测试覆盖跨句柄重启、最终回执重试、排队后新改动保留及冲突回滚，仅构建，尚未设备运行。

分批减少原始缓冲，但最终模型集合仍驻内存，合并是一份大事务；32 MiB 边界不代表已验证手表峰值内存或耗时。实际蓝牙、断电恢复、权限与后台耐久、并发回调仍必须实机验收。没有正式审计或发布通过结论。

## 日期精度升级边界

实时接收严格要求 protocol2/schema5；旧schema2/3/4只在本地备份恢复入口按原语义验证并迁移。归档的原始页版本必须一致，避免迁移掩盖混版。外层批次协议4；SQLite6再次清理未完成旧协议暂存，保留业务、设置、历史、已提交收据及确认修订，并重新排队。本版Android迁移和真实双端同步待设备验收。
