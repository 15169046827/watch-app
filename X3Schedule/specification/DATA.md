# 数据、备份与迁移

0.7.0开发候选使用SQLite6、Snapshot protocol2/schema5、BLE批次4和备份容器v1。旧任务的progress为空，沿用旧规则；新任务冻结等级、任务日、时区与额度。以下历史迁移按原版本理解；等级事件和更正、补录、冲突规则见PROGRESS.md。

全部应用数据存于各自私有 SQLite；不申请 Internet 权限，不自动上传，不记录私人名称或记录到日志。系统自动备份关闭。用户主动导出的文件可通过系统文件选择器保存到自己安装的网盘，导出后文件的保管归用户管理。

schema v1创建业务表和索引；v2添加suggestions；v3保留旧队列并创建新队列；v4增加分批暂存与收据；v5引入日历精度；v6清理未完成旧协议副本并重新排队，保留业务、历史、设置、设备选择、已提交收据及acked_revision。不支持降级，禁止通过清库掩盖迁移错误。当前JSON wire schema5，不支持的版本拒绝，旧版本仅在备份恢复入口明确迁移。

默认导出.x3backup分块备份，当前包含protocol2/schema5手机Snapshot的计划/删除标记、历史实例、不可变执行事件、请假与静音设置；不包含蓝牙地址、Android权限、已发送提醒标记、传输队列或suggestions接受记录。最大32MiB、1000计划、各50000实例/事件，完整性与语义验证后才能合并恢复。旧JSON仍受2MiB及原数量限制。文件未加密，开放格式见BACKUP.md。

恢复先检查文件并展示数量，再在单个事务中合并：新/较高版本计划可写入，旧版不回退；相同版本不同正文拒绝；事件 ID 去重并拒绝内容冲突；缺少的历史实例补入。恢复不删除原有记录。随后重建未来实例并标记待同步。外部文件不应当作可信输入，越界、错误版本、无效时间或非法来源直接失败。

用户可以删除未来计划，历史记录保留。第一阶段没有应用内“清空全部”，系统清除存储/卸载会删除该端私有数据库、配对选择和队列，外部备份不受影响；这些操作不会由开发工具自动执行。

执行型提醒默认在开始时、结束时、结束后 15/60 分钟调度。仅提醒型只发一次开始/提前提醒；待办仅在设置截止时发送一次截止/提前提醒。静音期间延后到静音结束，多项用一条隐去名称的通知合并。系统延迟投递、重启或改时后补发时，按实例时区再次检查实际投递时刻的静音设置；原到期时间与提醒键不变，超过既有 24 小时补发期限的项不再投递，避免静音延后无限延长补发。系统精确闹钟权限不足时使用非精确回退；强行停止等系统限制不能保证送达。重启、改时区/系统时间和应用覆盖更新后重新调度。提醒标记在本地持久化；手机不发布后台同步状态通知；手表开启后台连接服务时显示系统要求的常驻通知。

报告按计划/大类汇总，步骤不重复计分；有效请假从执行完成率分母扣除，计划履约率保留原计划分母。超额请假单列，24 小时逾期未确认按未完成参与统计。补录时间未知时只计完成，不伪造按时证据。默认每周有效请假 1 次、每月 4 次，可由大类/计划覆盖；这是可修改的实现默认值。

本地优化建议字段保留样本数、命中数、原因、原值、建议值、未来生效范围与用户接受状态；至少 3 次同类偏差可形成观察，至少 6 个样本且命中比例 ≥60% 才达到正式建议门槛。引擎不自动修改日程。手机提供本地分析、未来预览和明确确认；接受时计划变更、待同步修订和 suggestions 接受记录在同一事务中提交。接受记录仅本机保存，不包含在当前备份/同步 Snapshot；已接受的计划修改正常备份与同步。具体样本、阈值和局限见 OPTIMIZATION.md。

## 报告与单日修改

报告使用中国标准时间，日、周（周一至周日）、月、年及自定义范围采用开始含、结束次日不含的区间。只计入执行型中已保存、未取消且截至当前已开始的实例。请假额度先对全部已保存历史结算，再按报告日期/大类筛选，避免筛选重置全局额度。按历史实例分类和计划 ID 汇总，当前计划改名、改类或删除不会隐藏原有执行记录。按时率分母为扣除有效请假的应执行次数；完成时间未知不增加按时数。计划时长完成率为完成实例的计划分钟数/全部纳入实例的计划分钟数，分母为零时不显示百分比。读取报告使用独立数据库句柄和事务快照，统计在后台线程进行。

仅本次改时、取消、手工公司/法定排班和用户确认均先复制草稿，再定位所选日期实际所属的规则分段。保留的未来旧分段也可调整；过去日期、已删除计划和有效期外日期拒绝。已开始实例仍由重建时的历史冻结规则保护。保存前必须预览；草稿操作不会原地修改已存计划。

## 外部输入校验

备份与同步 Snapshot 在反序列化前检查严格 UTF-8 和 JSON：根必须为单个对象，协议约定的 11 个根字段全部存在且类型正确，拒绝 null 根字段、重复属性、尾随内容、注释和超过 16 层的值嵌套；浅层未知字段可忽略以兼容扩展。随后执行模型语义校验。设置的大类周/月额度表各最多 1000 项，名称须为 1–80 字符且不能全空白，额度须为非空非负整数；本地设置保存也执行相同校验。

ICS 导入采用严格日期解析，不将不存在的日期自动归并到其他日期。当前数据模型精确到分钟，因此含非零秒的 DTSTART/DTEND 拒绝；时长须在 0–24 小时内。拒绝空 UID、同一文件重复 UID 和 STATUS:CANCELLED，避免覆盖或复活事件；分别重复导入同一 UID 仍使用稳定计划 ID。此校验只覆盖已支持的 UTC 单次事件子集，不代表支持完整 ICS 规范。

## 容量可见性

首页后台读取一致性快照并测量下一份同步归档容量，数据容量页显示含归档头与校验尾的字节数及计划/实例/事件数量。0.3.0 使用 32 MiB、1000 计划、各 50000 实例/事件边界，80% 预警；无法生成合法有界批次时提示超限或校验失败，本地数据保留。手表只统计其本机事件。不是当前已发送页数、ATT 总流量或设备剩余空间。

测量复用实际分批编码，逐页计数并丢弃临时原始页，不改变待同步 revision 或创建发送队列。蓝牙发送与接收进度另行持久化；完整原始页限制为 128 KiB，完整解码模型仍驻内存，实际设备内存待验证。删除计划仍保留历史，不保证减小容量，没有自动归档。

## 分批状态与迁移

SQLite schema 4 增加 batch_out（manifest/游标）、batch_out_parts、batch_in、batch_in_parts、batch_receipts。初次建库依次应用所有迁移；支持 1/2/3 升级到 4，禁止降级。v4 不更改或删除旧 outbox 正文/修订，acked_revision 不推进；从权威模型生成新协议发送副本。单页暂存与整份应用确认是两级事务，详见 PROTOCOL.md。收据保留页摘要，不含正文；目前无自动清理策略。

## 0.5.0 数据迁移

SQLite v4 → v5 只清理旧 outbox、batch_out、batch_out_parts、batch_in、batch_in_parts；保留计划、实例、事件、设置、配对、legacy_outbox_v1、batch_receipts 与 acked_revision。递增本地 revision 后从权威数据重建传输副本，不能把清理当成同步完成。支持旧版本顺序升级，禁止降级或清库绕过错误。

dateOnly 区分具体时间和按天语义，daySpan 为含首尾的全天跨度（1–366天，待办固定1）；具体时间最长366天。按天待办以截止日次日零点为截止边界，在用户设置的默认提醒时刻提醒（未设09:00）。这些扩展只由 schema 4 解释，旧备份迁移必须验证不含扩展字段的非默认值。ICS 单次UTC子集仍限制24小时且不接入全天扩展。
