# 日程

开发中的下一候选为 **0.7.0/code17**：等级反馈、Recovery、任务日、补录与统计着色正在统一实现，尚未完成整阶段验收，不可据下方基线结论视为已发布。数据契约见 [等级事件模型](specification/PROGRESS.md)。以下 0.6.1 实机验收结论仅适用于原冻结安装包。

Android 手机与圆屏手表的本地日程工具（0.6.1，已通过批准范围内的正式实机验收）。手机创建和编辑三种用途的日程，手表查看日程、勾选待办和记录执行。无需账户、无服务器，不申请 Internet 权限。

手机在 Android 13+ 使用核心日历用途的 `USE_EXACT_ALARM` 标准权限，在 Android 12 使用需用户授权的 `SCHEDULE_EXACT_ALARM`，声明范围截止 API 32；手表不声明这两项权限。只为用户设置的开始、结束与主动延后登记 AlarmClock，自动补发/重试继续使用非精确闹钟。已在当前验收手机验证连续息屏投递、兼容升级恢复与真实重启恢复；其他厂商和系统版本仍需独立验证。

本版本停用手表本地日程通知，手机负责提醒，手表负责查看、记录和同步。手表断连时可读取已同步日程和记录完成，但不提供准时通知。关闭手机提醒后，手表不会兜底。已有仅手表提醒设置保留原数据，作为待处理设置持续提示用户选择手机提醒或不提醒，不自动开启手机提醒；备份和旧协议同步采用同样的兼容策略。新建与普通日程导入不能创建仅手表提醒。升级时主动取消旧手表闹钟和旧日程通知，后台连接状态通知仍保留。

手机通知显示日程名称和提醒原因（开始、待办到期、完成确认或主动延后结束），单项通知点击进入对应日程，应用已打开时也更新页面。多项同时到点时，通知标题包含首项名称与总数，展开显示最多六项及剩余数量，点击进入当天日视图；同一日程的过期开始和结束提醒合并为一项完成确认。通知保持私人可见性，系统锁屏隐藏敏感内容的设置仍生效；日程标题不写入诊断日志。

2026-10-10，0.6.1/code16 通过批准范围内的正式实机验收：手机息屏开始、结束、主动延后各三次，升级恢复、真实重启恢复、六种通知点击路径以及双端同步通过。手表提醒故障按移除正式发布范围处理，并未修复厂商调度限制。两端安装文件与冻结 Release APK 哈希一致；验收合成数据和额外验收应用已清除，原设置与连接授权保留。此结论不等同于已公开发布，也不覆盖其他设备。隐私页发布者文案仍显示 0.6.0，为 P3 延后项，下次版本改为动态读取。

## 模块与规范

- domain：纯 Java 周期规则、执行记录、分层报告、提醒策略、备份与同步格式、自然语言草稿和 ICS。

## 构建与验证

使用 JDK 17、Gradle 8.9、Android SDK 35 / build-tools 34.0.0。在忽略的 local.properties 中配置 SDK，从本目录运行：

~~~text
gradle checkstyleMain checkstyleTest checkstyleAndroidTest :domain:test :shared:testDebugUnitTest :phone:testDebugUnitTest :watch:testDebugUnitTest :shared:lintDebug :phone:lintDebug :watch:lintDebug :phone:assembleDebug :watch:assembleDebug :phone:assembleDebugAndroidTest :watch:assembleDebugAndroidTest
python tools/test_schema.py
~~~

仓库 Android CI 包含同等日程验证步骤。手机和手表 Android 测试包共用 StoreTestRunner，使用隔离合成数据库且结束前清理；构建成功不等于设备测试通过。存储回归包含非空v4/v5→v6升级与再次打开，核对业务、设置、配对元数据及收据保留，未完成传输清理和重新排队；ProgressStoreChecks覆盖失约、自行补做、手表权限、回滚和恢复/同步幂等。2026-10-17两端各202项真实检查通过；期间发现并修复迁移注释分号被当作SQL的故障，增加独占行注释过滤及回归。正式升级和新功能交互仍待验收。

完整界面验收可使用 `validation` 构建类型；它与正式版本共用生产代码，但使用独立 UID/数据目录和“日程验收”名称。手机包名为 `com.canace.x3schedule.phone.validation.phone`，手表为 `com.canace.x3schedule.validation`，均使用共享 Debug 签名，不作为发布产物。

~~~text
gradle -PscheduleTestBuildType=validation :phone:checkstyleAndroidTest :phone:lintValidation :watch:lintValidation :phone:assembleValidation :watch:assembleValidation :phone:assembleValidationAndroidTest :watch:assembleValidationAndroidTest
~~~

安装前对四个 validation APK 单独使用 `apksigner verify --print-certs` 核对共享证书。`-e calendarFixture true` instrumentation 模式只接受上述两个包名，且要求库内无计划/事件、未选择同步设备；它不会清库或重置现有数据。成功后保留 43 个合成计划与 3 条历史完成记录，提醒关闭，供重复修改范围、历史保留及密集布局验收。禁止给验收版本配置正式同步伙伴。普通 Debug/Release 产物不含此 fixture；不传属性时测试构建类型仍为 Debug。

`-e progressFixture true` 使用相同的包名/空库/无伙伴限制，在单一事务中生成昨天的9项等级任务和9条事件：四档成果、请假、未反馈、原时段未做后自行完整补做、二分完成、不定时最低行动。每项关闭提醒，不删除或覆盖原数据。失败整体回滚，非空库拒绝重复生成；该模式用于日/周/月配色、反馈、补录、更正及圆屏检查，不能替代正式补救实时冲突、提醒或双端同步实测。验收后须按登记清理合成库，不能给其配置正式伙伴。

手机 validation 测试包还支持 `-e saveLifecycle true`：在真实 Activity 中运行生产预览组件，检查不确认不保存、确认后禁用重复点击、页面销毁后继续提交、历史事件保留及不再触发页面导航。该模式仅接受手机验收包且要求未配置同步伙伴；成功会在验收库保留一条关闭提醒的合成计划。测试专用屏障通过反射延迟本应用的保存执行器（最多10秒），不访问 Android 隐藏 API，不模拟真实断电或保存中强杀进程。Activity 启动有15秒超时，使用测试自动化连接避免厂商后台启动差异。

`-e configuration true` 仅在无同步伙伴的手机 validation 包中运行真实页面旋转检查：日视图宽度、选中日期/模式、周视图横向位置、编辑字段和选项、未确认预览以及排队保存时的确认状态。通过 Activity 请求方向并恢复原请求值，不修改设备全局旋转设置；成功后验收库增加一条关闭提醒的合成计划。

`-e uiState true` 检查表单恢复及主按钮实际背景像素，包括首次显示、禁用和重新启用。实机发现部分框架会保留 Ripple 子背景的初始禁用色；组件安装背景后显式传播当前状态，避免白字落在浅色背景上。

测试包的 `-e uiField <字段> -e uiText <合成值>` 仅通过公开无障碍接口填写指定任务字段或系统保存文件名，不更改输入法。运行者必须是独立 validation 包，前台只能是日程应用或系统文件选择器；字段必须唯一且在白名单内。任务值限 `QA07-` 前缀的 ASCII 合成文本，文件名限 `x3schedule-*.x3backup`；不能用于权限弹窗或任意应用。

不要在同一 validation 应用等待系统文件选择结果时启动其 instrumentation 来填写文件名：测试启动会重启目标进程，可能打断待处理的系统结果并留下空文件。该工具可填写另一个日程应用的文件选择窗口；验收应用自己的备份优先保留不存在的默认文件名，保存成功后再重命名。

`-e progressLifecycle true` 使用独立手机验收库及真实对话框，验证原时段反馈后的自动补救邀请能够在详情控件替换后继续刷新，并验证离开任务页面后的保存不会触发导航。成功保留一个关闭提醒的合成计划及三条事实；不清除旧数据。`-e progressConflictUi true` 可在两端运行，使用生产预览入口核对硬冲突阻止、前往手机的明确提示及没有启用记录，并在验收应用自己的外部目录保存仅含合成界面的截图。

`-e recoveryFixture true` 仅向无伙伴的 validation 主库添加三个关闭提醒的本地界面用例：原时段已结束、四分钟后的单分钟补救、十分钟后的强制冲突。已有同批标题拒绝重复添加，不覆盖原记录。它不承担跨设备同步验收。

`-e reminderFixture seed|seed2|inspect` 仅用于无伙伴手机 validation 包。seed 添加一个三分钟后开始、持续一分钟的新等级任务，seed2 使用独立标题复测，并只在验收应用内关闭静音时段以便观测；正式设置不变。正常打开验收应用确认闹钟登记后再息屏，测量窗口内不要启动 instrumentation，否则会影响进程及闹钟。全部到点后，inspect 只读取本应用指定合成通知的标题、原因、投递时间和不可变跳转标识。测试后通过卸载登记的验收包清理合成数据、通知及闹钟。

双端 validation 测试包支持由主机协助的 `-e transactionCrash before|after -e crashId <32位小写十六进制新ID>`。每次必须使用新 ID，测试只打开 `schedule-test-crash-<ID>.db`，不打开 `schedule.db`。主机等到 `Crash boundary armed`（或对应私有 `files/schedule-crash-<ID>-armed` 标记）后，在30秒内终止该验收包进程；随后以同一 ID 运行 `-e transactionCrash recover-before|recover-after`，核对数据库完整性、计划、实例、历史、设置和同步修订。手机可通过验收包自身 UID 终止进程，平台不支持时可用 `am force-stop <验收包名>`，须记录实际方式。`before` 用测试外层事务包住真实 `Store.saveAll`，在数据已修改但外层尚未提交时暂停；超时自动回滚。`after` 在真实批量保存返回后暂停。此检查证明受控事务边界的进程终止恢复，不等同于任意写入指令处强杀或物理断电；合成数据库和比对文件保留供核查。

存储测试超过 30 秒仍未结束时，测试包输出执行线程栈辅助定位停滞；诊断不读取日程内容，也不自动将等待判为通过。

显式传入 instrumentation 参数 `blePeer` 可运行两台已配对设备之间的合成 BLE 验证。先启动手表，再启动手机；两端需具备蓝牙权限，参数为对方的已配对地址。该模式在独立测试数据库中验证跨页日程传输、26 小时跨日日程、三天全天提醒、按天截止待办、自定义默认提醒时间和手表完成记录回传，初始及恢复传输各最多等待八分钟，主机控制命令最多等待五分钟，不修改正式日程。合成传输注入空提醒回调，避免同步完成后重排验收主库提醒；生产构造入口保留真实提醒重排。它不能代替断连恢复、息屏与后台可靠性验收。

同时设置 `-e bleProgress true` 时改用单项无提醒等级任务：手机原时段Minimum→手表启用未来补救→手机在开始前取消→两端核对三条原始事实、因果状态及待同步为0。它使用相同专用BLE标识和随机测试数据库，结束清理；不能与旧传输恢复模式混用，也不替代补救到点后的交互验收。前台对照使用 `-e bleForeground true`，应确保蓝牙已真正开启后再启动测试；公开开关返回成功不等于启动完成。若为排除并行服务临时退出正式应用，测试后必须重新打开正式两端并核对连接与提醒恢复。

两端另传 `-e bleRecovery <相同的全新32位小写十六进制ID>` 可运行主机协调的断连补传检查。首次同步后，测试通过私有目录 `files/ble-recovery-<ID>/phase` 报告 `ready`；主机向该目录的 `command` 写入控制词：先对手表写 `disconnect`，等手表报告 `offline` 后对手机写 `edit`，等手机报告 `offline` 后让两端回到系统首页并息屏，再对两端写 `recover`。手表重新开放验收GATT服务，手机保留原连接对象并自动重试；两端以4计划、2事件、待同步队列清零和原历史不变作为补传条件，全程每500ms检查屏幕仍非交互。双方报告 `recovered` 后，主机对两端写 `finish` 才拆除连接，避免最终ACK竞态。命令等待2分钟、恢复等待4分钟，超时判失败；目录ID必须全新，文件控制入口仅在测试包内。

这项检查保留 instrumentation 进程，使用验收专用蓝牙标识和独立临时数据库，只证明应用级GATT断开/自动重连及指定息屏窗口内的传输。它不切换系统蓝牙，不模拟真实离开覆盖范围，不能代替生产伴随设备服务、Doze、系统清理或重启耐久验证。主机应记录并恢复临时蓝牙权限及原亮屏状态；按需由用户解锁，不能绕过锁屏。

可另加 `-e bleForeground true` 做独立亮屏前台对照：两端先由用户正常解锁，测试打开仅验收版包含的“连接恢复对照”页面并保持屏幕亮起，结束后关闭页面。该页面不打开日程数据库，只存在于验收版，使用系统 `DUMP` 权限限制入口，由调试工具显式打开（等待最多15秒）；普通应用不能调用。手机端的规范门禁也覆盖这份双端共用的验收源代码。主机此模式不返回首页、不息屏，其他断连/双端离线改动/补传及历史校验相同；结果标明 `foreground=true`，不能计作息屏通过。

定位失败时可在 Android 10+ 另加 `-e bleAwakeCpu true`：测试自动化只临时采用 `WAKE_LOCK` 权限，获取最多10分钟的部分唤醒锁，并在收尾释放权限身份和锁。它只用于区分 CPU 挂起与其他故障，不能阻止厂商冻结进程；生产应用没有新增唤醒锁权限或保活代码。恢复阶段日志包含连接状态、队列/暂存计数及实际时间和CPU运行时间，只有完整结果才可标为通过。厂商省电策略导致的暂停须通过用户正常设置单独复核，并记录设置前后及恢复情况。

两个 Debug 应用使用工作区已有共享证书，构建时校验密钥身份，不允许生成替代密钥。构建后从工作区独立检查 APK：

~~~text
scripts/verify-debug-signatures.ps1 -Product X3Schedule -AndroidSdk <SDK>
~~~

APK 位于各模块 build/outputs/apk/debug/，不纳入 Git。Release 使用独立签名配置；缺少配置、摘要错误或使用 Debug 证书时必须失败。开发构建不等于获准发布。

## 使用与连接

日历刷新期间保留原日历，较慢的刷新显示半透明遮罩与可见区域中央的加载圈；快速刷新不额外显示加载提示。加载期间暂时阻止日历操作，失败保留旧画面并提示重试。

在手机创建计划或输入“每周一三五早上 6:30 到 7:30 晨跑”，核对实例和重叠提示后保存。在系统蓝牙设置配对两端，再在应用“连接与权限”中授权并选择对方。连接后按 128 KiB 分批传输，逐批保存接收进度，整份校验并事务合并后才确认已同步；断开时保留本地日程、执行记录和待同步提示。手表不能创建或编辑周期计划。

Android 12+ 手机可通过系统窗口关联所选手表，使用伴随设备观察进行后台恢复。手机声明观察权限；共享库声明该接口的权限契约，手表打包时明确移除这项手机专用权限。观察权限或关联缺失时返回失败，不绕过系统授权。

手表提供可关闭的后台连接服务和系统要求的常驻通知。较旧手机主要依赖应用前台连接。息屏、Doze、重启和厂商清理后的真实可靠性尚待设备验证，不能仅凭可构建代码作出保证。

## 状态、排班与报告

开始、完成、继续 5/10/15/30 分钟、未完成、请假都会生成不可变记录。超过结束时间进入待确认，24 小时后为逾期未确认，补录会重算报告。“当时已完成但忘记确认”不伪造精确时间。已开始或已有记录的实例保持历史快照。

- 支持按天、指定星期、月内第 N 个星期几、工作日、大小周和轮班等周期。
- 支持保持计划 ID 的“从指定日期起”分段编辑；单次改时、取消和手工排班确认作用于日期实际所属的分段。预览不会原地修改原计划。
- 内置 2025、2026 年中国全国日历，来源见 specification/CALENDAR.md。公司排班优先，争议日期提示确认；缺失年份退回周一至周五，可从本地文本导入更新。
- 用途由用户选择：执行型记录完成；仅提醒型只发送开始/提前提醒，不催促打卡；待办可不设时间或设置截止，支持完成和重新打开。用途与内容大类分开，后两者不计完成率、请假额度或优化分析。
- 手机提醒支持全局默认、单计划覆盖及手机总开关；系统延迟投递时再次检查静音，超过 24 小时的旧提醒不再补发。关闭手机提醒不会产生手机同步状态通知。
- 报告支持日、周（周一至周日）、月、年、自定义范围，统一使用中国标准时间，按总计、大类和计划汇总保存的历史。
- 只计入执行型中已保存、未取消且截至当前已开始的实例。尚未开始的未来项不进入分母，缺失历史不会被补成未完成。
- 有效请假从执行完成率及按时率分母扣除；计划履约率保留原计划分母。超额请假、待确认和逾期未确认分别列出。
- 完成时间未知只计完成，不计按时。计划时长比例是完成项的计划分钟占比，不代表实际耗时；时间点任务计次数，零分钟分母不显示百分比。

## 当前边界

本项目仍在开发，规范检查、主机测试和 APK 构建不能证明真机提醒、BLE 或界面可靠。

- 蓝牙同步使用批次protocol4：一份归档最大32MiB、1000计划、各50000实例/事件，每批128KiB。发送快照与游标持久化，接收收齐校验后原子合并，最终ACK丢失可幂等重试；未完成批次不显示已同步。两端须为0.7.0或兼容版本；新模型的真实双端和后台验收尚未完成。
- 首页和数据容量页测量下一份归档容量，80% 提示接近上限；不是当前发送进度。完整模型仍驻内存，不能声称无限历史；没有自动归档或增量同步。
- 手机新增 .x3backup 分块备份：独立上限 32 MiB、1000 计划、各 50000 实例/事件，后台导出和校验，确认后事务合并恢复，兼容旧 JSON。完整性校验通过前不写数据库；不是无限容量，备份和同步分别检查各自限制。格式和内存边界见 specification/BACKUP.md。
- 手机“本地优化建议”分析最近 90 天当前定义的已完成记录，展示开始偏晚、时长不足、确认偏晚、前序重叠及星期规律。达到门槛的开始/时长建议可预览并确认应用到未来；其余仅观察。
- ICS 不含待办与完成记录，完整数据用分块备份。执行型/仅提醒型可保留用途字段，普通外部事件默认仅提醒型。导出将未来 180 天展开为 UTC 单次事件；导入只支持含 UID、SUMMARY、UTC DTSTART/DTEND 的单次事件。无效日期、非零秒、超过 24 小时、取消事件、空或文件内重复 UID 会拒绝。复杂周期、全天、浮动时间和时区参数不支持，系统日历双向同步后置。
- 系统自动备份关闭；用户主动导出的备份未加密，须自行妥善保管。
- 已使用系列日历图标；手机启动器、大字体首页与横屏布局已实机检查。手表启动器圆形图标与点击启动已实机检查；权限撤销和后台耐久仍待验收。
- 目前没有代码审计或正式发布通过结论，未包含在其他产品已发布的安装包中。

协议、冲突、备份和迁移边界见 specification/PROTOCOL.md、specification/DATA.md；本地分析的有效样本、阈值与局限见 specification/OPTIMIZATION.md。开发测试只使用合成数据，操作真实设备前须取得具体设备连接确认。


当前开发候选0.7.0（versionCode17）；实时分批协议4，内部Snapshot为protocol2/schema5、SQLite6。两端须为0.7.0或兼容版本；旧实时协议拒绝，旧手机JSON及分块备份按原版本语义验证后迁移，旧任务不自动转换等级规则。用途与基础迁移见specification/TYPES.md，新等级契约见specification/PROGRESS.md。

0.6.0 新增双端首次运行说明及“隐私与本机数据”。清除区分日程与记录、缓存、设备连接配置、全部本机数据；影响和二次确认见 [隐私说明](PRIVACY.md)，版本变更见 [版本记录](CHANGELOG.md)。日程清除会暂停本机同步，避免另一设备的数据立即传回；在连接页恢复同步前请确认另一设备保留的数据是否需要继续使用。

## 基础日历（0.5.0）

手机默认进入月历，可选日期、切换周/日时间轴、回到今天、从所选日期或空白小时新建。全天与按天截止放在独立区域；未定期待办仍在日程页。编辑使用摘要行和同一面板的日期/分钟选择器，明确开始、结束及跨日范围；提醒支持全天，待办支持无截止、按天截止或精确到分钟。按天提醒可设置默认时刻，未设置为上午9点。

重复日程点击编辑后立即选择影响范围，再进入编辑页；删除也先选范围并确认。可只改一次、从某次起改未来或改系列未来部分，保留已有历史。执行步骤和请假额度放在二级设置，提醒仅提供手机或不提醒。详情、待确认、当前/下一项、报告和备份入口仍在。

月日、按年重复、明确多日及全天范围引入 Snapshot schema 4 / SQLite 5；升级仅清理未完成传输副本并重新生成，保留业务历史与已提交收据。旧备份只通过恢复入口迁移，实时同步拒绝旧语义。规则及验收边界见 specification/CALENDAR_UI.md。

本版已通过电脑端单元测试、代码规范、Android Lint、双端应用与测试包构建、共享签名检查及相关安全门禁；已完成双端覆盖安装及部分实机验证。周视图横向恢复、密集事件聚合及后台布局/预览已实现；长标题/大字体、真实触控和设备峰值内存仍需验证，不构成正式审计或发布结论。

## 独立后台服务验收

正式故障定位可显式传入 `-PscheduleReminderDiagnostics=true`。默认值为 `false`，其它值拒绝构建。
手机生产调度使用 `setAlarmClock`，仅登记用户启用的未来开始、结束、截止或主动延后确认提醒。
系统可能显示下一闹钟标记，点击打开对应日程；API31+权限拒绝或撤销时显示可能延迟并使用非精确路径。
自动15/60分钟催促及过期补发只使用非精确恢复性提醒，不承担准时承诺；待确认状态持续保留。
旧 `scheduleAlarmClockExperiment` 参数仅保留构建参数兼容性，不控制手机生产调度；正式版关闭诊断及该旧参数。
手表在调度入口无条件取消两个旧闹钟身份后返回，不登记任何日程通知。
开启后 `ScheduleReminder` 日志仅包含闹钟请求、接收器、后台工作和通知提交的时间与数字状态，
不含日程标题、内容、实例 ID 或设备地址。定位构建不能作为最终发布产物；结束定位后必须关闭开关、
重新验证签名与产物身份并复验真实 Release。系统调度延迟仍须完成设备验收，不据此宣称准时投递。

`background` 构建使用完整生产 Activity、伴随设备服务和手表前台服务，应用名为“日程后台验收”。其独立包名后缀为手机 `.background.phone`、手表 `.background`，BLE服务/特征命名空间另行隔离；正式版与普通validation库均不参与。构建使用 `-PscheduleTestBuildType=background` 和 `assembleBackground` / `assembleBackgroundAndroidTest`，并运行 `lintBackground`。

测试runner的 `backgroundFixture=seed` 与 `backgroundPeer=<已配对地址>` 只允许在此两个精确包名和专用BLE标识下写入空库，创建两个关闭提醒的合成计划并选择已配对伙伴；禁止覆盖已有数据。`complete` 只为已同步的手表待办记录一次完成，`add` 只为初始手机库增加一条提醒，`inspect` 输出合成计数。它们都是准备或结束检查，会影响进程寿命，不能在后台测量窗口内运行。测量前必须退出instrumentation，正常打开应用并由用户确认系统伴随关联；窗口中只观察系统服务和屏幕状态，结束时停止验收应用后读取一致数据库进行核对。没有诊断前台页、额外唤醒锁、强制Doze或系统电源策略修改。
