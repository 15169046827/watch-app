# 版本记录

## 0.7.0（开发候选，未完成设备验收）

- 新执行任务支持自定义完整、基本和最低行动标准；全部留空时采用完成/未完成。实际成果等级和计划执行得分分别保存、展示。
- 支持可选正式补救、显式冲突处理和逐次让位确认；手机负责时间表编辑，手表仅反馈及启用无冲突补救。原时段与补救失约独立累计，未反馈不自动记作未进行。
- 任务日默认凌晨4点，可配置；实例冻结原规则、时区、日边界和请假额度。区分当天自行补做、过去三任务日补录和保留原始事实的成果更正，已确认未进行不可撤销失约。
- 日/周等级卡片和反馈选项显示成果颜色及文字，月视图显示执行得分与待确认标记；报告区分正式补救行动、升档、完整成果和自行补做。
- SQLite升级至6，Snapshot schema5、BLE批次4，两端须同步升级；旧备份通过明确迁移恢复，原任务保留旧规则。
- 隐私页动态显示安装版本，通知采用产品单色图标，保留既有启动器视觉。
- 修复真实SQLite初始化/升级时SQL注释内分号被错误执行的问题；两端非空v4/v5升级、重新打开与事务检查各202项通过，实际功能验收仍在进行。
- 本条为开发记录，不代表正式发布或设备验收通过；0.6.1冻结验收结论保持独立。

## 0.6.1（2026-10-10，批准范围内实机验收通过）

- Android 13+ 手机采用核心日历用途的准时提醒权限；手表不声明精确闹钟权限。
- 通知显示具体日程名称及提醒原因，修复冷启动、后台和前台点击跳转，并在升级时一次性取消旧通知入口。
- 验证手机连续息屏开始、结束、主动延后各三次，兼容升级恢复、真实重启恢复、六种通知点击路径及双端同步；两端冻结 Release 安装文件哈希一致。
- 清除合成验收数据及额外验收应用，保留正式应用、设置和连接授权。
- 手表本地定时通知经批准移除发布范围，厂商调度限制未修复；自动催促仍可能因省电延迟，其他设备未纳入本次结果。
- 已知 P3：隐私页静态发布者文案仍显示 0.6.0，下次正常发布改为动态版本。验收通过不表示已公开发布。

## 0.6.0（待发布验收）

- 手机用户指定的未来提醒采用系统闹钟，权限拒绝时明确提示可能延迟；自动催促和补发使用非精确恢复路径。
- 经用户批准移除手表本地定时通知；保留查看、完成记录和同步，升级主动取消旧提醒。
- 新建仅提供手机提醒或不提醒；旧仅手表设置保留并提示显式处理，备份及协议数据格式不变。

- 双端首次运行说明本机数据、离线边界、权限、未加密备份和清除入口。
- 新增“隐私与本机数据”，区分日程与记录、缓存、连接配置及系统全部数据清除，并二次确认。
- 分类清除等待保存、备份和蓝牙操作结束；日程清除后暂停同步，恢复同步由用户选择。
- 提醒重建在后台队列执行，定期任务完成后再通知系统；清除数据也等待提醒队列结束。
- 修复自然语言任务名称中的“下午”或“晚上”错误改变日程时间的问题。
- 日历刷新保留原画面，以延迟出现的半透明遮罩和居中加载圈提示进度，避免快速刷新闪屏。
- 保持 BLE protocol 3、Snapshot schema 4、SQLite schema 5 和备份容器 v1；未改变既有数据格式。
- 正式验收完成前不能将本版本标为生产发布通过。
