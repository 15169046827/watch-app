## 1. 通用视觉原则

- 母版只作为构图参考，生产图标必须用矢量或代码重绘，不能直接裁切概念图。
- 采用纯平面设计，不使用渐变、投影、发光、浮雕、3D 或拟物效果。
- 核心符号以画布几何中心为基准居中；允许少量光学校正，但同一平台的主体大小、重心和线宽必须协调。
- 48 px 下仍需清楚辨认；删除不会影响识别的细节。
- 暖白与深炭作为共同前景色，各 App 只改变系列主色与核心符号。
- Android 与 Windows 使用不同的外轮廓策略，禁止直接共用同一张最终位图。

## 2. Android 图标规则

- API 26+ 使用标准 adaptive icon：纯色 background layer 完整覆盖画布，透明 foreground layer 承载符号，由 Android 系统施加圆形或圆角蒙版。
- 48×48 fallback/静态母版的主前景默认落在 9～39；细小点缀最多放宽至 7～41。
- adaptive foreground 以 `(24,24)` 为中心统一缩放至 `0.72`；缩放后的主要内容通常落在 13～35，点缀最多放宽至 12～36。
- 在 OPPO Watch X3 圆形蒙版中，最终前景目标占图标直径约 60%～68%，四周保留均匀底色边框。
- API 25 及以下提供全画布正方形 fallback；Manifest 的 `android:icon` 和 `android:roundIcon` 指向同一套资源。
- Android 资源不得预制圆角底板或透明外边距，否则会与系统蒙版形成二次缩放。

## 3. Windows ICO 设计规范

### 3.1 显示模型

Windows 桌面、开始菜单和快捷方式通常按 ICO 自身透明度原样显示，不会像 Android adaptive icon 那样自动裁切。因此 Windows 必须使用：

`透明正方形画布 + 居中的圆角系列色底板 + 居中的核心符号`

不得让系列色覆盖整张 ICO 画布，否则会显示为突兀的完整方块。

### 3.2 512×512 母版参数

| 项目 | 推荐值 | “听读工坊”当前值 |
| --- | --- | --- |
| 画布 | 512×512 RGBA，初始完全透明 | 512×512 |
| 圆角底板占比 | 82%～84% | 420×420，约 82.0% |
| 透明外边距 | 每边约 8%～9% | 46 px，约 9.0% |
| 底板圆角 | 底板宽度的 18%～22% | 84 px，约 20.0% |
| 主体包围盒 | 画布宽高约 55%～65% | 主要窗口约 320×304 |
| 四角 Alpha | 必须为 0 | 0 |
| 底板中心 Alpha | 必须为 255 | 255 |

抗锯齿边缘允许出现 1～254 的中间 Alpha；只有画布外角必须完全透明、底板主体必须完全不透明。

### 3.3 构图与颜色

- 圆角底板使用对应 App 的系列主色，不添加描边、阴影或发光。
- 核心符号在底板内居中，优先使用暖白和深炭；细节不可贴近底板边缘。
- 不添加第二层白色外卡片。符号自身需要的暖白窗口、纸张或书页属于图形内容，不属于外部承载底板。
- 16/24 px 下允许简化细线、装饰点和内部间距，但不得改变外轮廓、透明留边或主体重心。

### 3.4 交付资源

每个 Windows App 至少保留：

- 一份可编辑矢量母版，例如 `app-icon.svg`；
- 一份 512×512 RGBA PNG，用于窗口图标和人工预览；
- 一份包含 `16/24/32/48/64/128/256 px` 原生条目的 ICO，用于可执行文件、快捷方式、开始菜单和任务栏。

所有 ICO 条目从高分辨率透明母版高质量缩放；不能只嵌入一张 256 px 图片交给 Windows 临时缩放。

### 3.5 Windows 接入规则

- 打包器必须将新 ICO 写入可执行文件；窗口运行时图标使用同系列透明 PNG。
- 开始菜单和桌面快捷方式必须明确引用新可执行文件的图标，或引用随包稳定存在的 ICO；不能指向临时构建目录。
- 更新图标时安全刷新现有快捷方式，不修改其目标程序、工作目录和用户数据。
- 如果程序正在执行转换，不得为替换可执行文件而强行结束进程；可先生成并验证资源，待转换安全结束后再完成打包替换。
- Windows 图标缓存只允许使用最小、可逆的刷新方式；不得删除用户的其他快捷方式或大范围清理系统图标缓存。

### 3.6 Windows 验收标准

自动检查：

- PNG 与每个 ICO 尺寸的四角 Alpha 均为 `0`；
- 底板中心 Alpha 为 `255`；
- 48 px 及以上的非透明包围盒占画布 81%～85%；
- ICO 确实包含 16/24/32/48/64/128/256 px 七档条目；
- 打包后的 EXE、窗口图标和快捷方式引用的是同一版图标。

人工检查：

- 在 Windows 桌面、开始菜单和任务栏分别查看；
- 不出现完整不透明方块；
- 圆角底板与同屏常见 App 的视觉大小协调；
- 透明留边均匀，主体居中，没有偏上、偏下或贴边；
- 浅色和深色桌面背景下均能识别；
- 16/24/32/48 px 下仍能识别核心功能。

## 5. 兼容性与项目边界

- 图标更新不修改项目目录、applicationId、Java/Kotlin 包名、Windows 内部代码包、数据目录或签名身份。
- Android 覆盖安装不得通过卸载解决签名问题；Debug APK 继续使用工作区共享签名。
- 每个开发任务只修改其负责项目，完成构建、资源校验、目标平台实机/桌面验证，并更新各自 Wolai 文档。
